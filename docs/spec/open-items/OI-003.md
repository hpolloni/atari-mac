# OI-003: Cartridge interface signatures

## Question

Which Rust interface does the cartridge have?

## Context

`system.md` asks for `read(&mut self)`, `peek`, `write` and `access_control(..) -> Option<u8>`. `media.md` gives `read(&self)` and an `access_control` that returns nothing. A `$D5xx` read must be able to return a byte that the cartridge drives.

## Options

1. Use the `system.md` interface.
2. Use the `media.md` interface, and add a return value to `access_control`.

## Recommendation

Option 1. It supports cartridges that drive `$D5xx` reads and ANTIC side effects (OI-002).

## Decision

Decided on 2026-11-19 by the lead (an integration defect: two designs gave different signatures). The `system.md` contract is used, with the media functions `from_raw`, `from_car`, `kind` and `cold_reset`:

`read(&mut self, addr) -> Option<u8>`, `peek(&self, addr) -> Option<u8>`, `write(&mut self, addr, value)`, `access_control(&mut self, addr, Option<u8>) -> Option<u8>`, `rd4()`, `rd5()`.

No supported cartridge kind drives the bus in `$D5xx`, so `access_control` returns `None` for all of them, and the CPU reads `$FF`.

Changed: `media.md` ("Cartridge", call contract).
