# OI-044: The BRK cycle that loses an NMI

## Question

When an IRQ or BRK sequence starts on cycle 3 or 4 of a scan line with an NMI, is the NMI lost, or does it hijack the sequence?

## Context

HRM 3.4 text: "this effect occurs if a BRK instruction begins execution at between cycles 4-8 of a scan line". HRM Figure 2 caption: "Unusual behavior starts when the IRQ sequence begins on cycle 4, which causes the NMI to be lost entirely." REQ-122 follows Figure 2.

ACID800 `cpu_bugs.s`: "This needs to start executing at cycle 4-8. If it executes at cycle 3 then it blocks the NMI!" This agrees with the HRM text: the loss is on cycle 3, and cycle 4 is a hijack. So Figure 2 can be one cycle off.

## Options

1. Keep Figure 2: a start on cycle 4 loses the NMI.
2. Follow the HRM text and ACID800: a start on cycle 3 loses the NMI, and cycles 4-8 hijack.

## Recommendation

Option 2. Two sources agree, and one of them is a test that runs on real hardware.

## Decision

Not decided.
