# OI-053: Host control of the paddles

## Question

Which host input sets the paddle values in the macOS frontend?

## Context

REQ-535 lets the host set the scan count of each input `POT0-POT3` (`Machine::set_paddle`), and the tests check it. No requirement maps a host input to a paddle, so in the window `PADDLE(0)` always reads 228, which is the value with no paddle. The SLICE-04 goal says that "the paddles change the values that the program reads".

HRM 7.2 gives the paddle range as 1 (fully counterclockwise) to 228 (fully clockwise). Each controller port has two paddles, so the 65XE has up to four (REQ-535). A paddle has one button. HRM 7.2 (Paddle trigger): "The paddle trigger is connected to the PIA ports, as with the joystick direction inputs." The button of POT0 reads as the left direction (PORTA bit 2), and the button of POT1 as the right direction (bit 3).

## Options

1. No host control. Paddles are set only by the tests. Paddle games cannot be played.
2. The mouse X position in the window sets paddle 0, and the mouse button is the paddle 0 button. The left edge of the window is 228 and the right edge is 1, and the requirement states the exact mapping.
3. Like option 2, plus the mouse Y position sets paddle 1.
4. Keys: two keys turn paddle 0 left and right at a fixed rate, and one key is its button.

## Recommendation

Option 2. A mouse gives the fast, absolute position that paddle games need, and it is the usual choice of other emulators. Keys (option 4) are too slow for most paddle games. Option 3 is rarely useful, because one hand cannot control two paddles.

## Decision

Not decided.
