# OI-040: The REQ-623 test with a user-supplied OS ROM

## Question

How does the test `req623_fast_sio_xl_os` behave when the user has not supplied an Atari XL/XE OS ROM?

## Context

REQ-623 criterion 7 says that the test prints a message that names the missing ROM and passes with no check. `docs/design/media.md` said that the test is ignored with the reason `needs a user-supplied Atari XL/XE OS ROM: REQ-623`, and fails with `HarnessError::Missing` when it runs without the ROM. The two texts do not agree.

The REQ-027 gate now permits only the ignore reason `planned: SLICE-NN`. A test that needs a file that the project cannot download does not fit that rule.

## Options

1. Keep criterion 7: the test passes with no check when the ROM is missing. The test is not ignored. The risk is a test that passes without a check.
2. Add a second permitted ignore reason to REQ-027, for example `needs user file: <file>`, for tests that need a file that the project cannot download. The test fails when it runs without the file. Criterion 7 changes to match.
3. Remove criterion 7. The SIOV shortcut with the original OS stays untested.

## Recommendation

Option 2. A test never passes without a check, and the gate still controls each ignore reason.

## Decision

Not decided.
