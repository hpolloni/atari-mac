# OI-002: Side effects of ANTIC DMA reads in $D500-$D5FF

## Question

Can an ANTIC DMA read of `$D500-$D5FF` switch a cartridge bank?

## Context

REQ-609 requires it (HRM 8.1 warns about it). REQ-213 says that DMA reads have no side effects. The draft trait `DmaMemory::dma_read(&self)` cannot change state.

## Options

1. DMA reads of `$D5xx` reach the cartridge control. `dma_read` takes `&mut self`.
2. DMA reads have no side effects. REQ-609 criterion 2 is withdrawn.
3. ANTIC reports each DMA address to the machine, and the machine calls the cartridge.

## Recommendation

Option 1. It follows the hardware. Change REQ-213 to name this one exception.

## Decision

Decided on 2026-11-19 by the lead (an integration defect: REQ-213 and REQ-609 contradicted each other). HRM 8.1 warns that ANTIC reads of `$D5xx` can switch banks, so the hardware decides.

1. `DmaMemory::dma_read` takes `&mut self`.
2. A DMA read of `$D500-$D5FF` calls `Cartridge::access_control`, then the machine updates `TRIG3` from `rd5()`. A DMA read of the other I/O pages has no side effect and gives `$FF`.
3. REQ-213 names this one exception. Its criterion 4 now expects exactly one cartridge access for one DMA read of `$D500`.

Changed: REQ-213, `antic.md` (`DmaMemory`, `tick`), `system.md` ("ANTIC", "ANTIC DMA"), `media.md` (call contract, open issue 3).
