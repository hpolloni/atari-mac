# OI-055: Lower-case letters and control characters in --bas files

## Question

How does `--bas` type lower-case letters and the control characters TAB, ESC and BACK SPACE of a text file?

## Context

REQ-080 criterion 9 says that the typed program is exactly the program of the file. Before 2026-11-20, `--bas` typed each lower-case letter as upper case. The fix of 2026-11-20 types lower-case letters as lower case (with the CAPS key). Thus a file with lower-case keywords, for example `10 print 1`, now gives a BASIC error: Altirra BASIC 1.59 does not accept lower-case keywords. The examples in `examples/` have only upper-case letters, so they still work.

TAB, ESC and BACK SPACE have keys on the Atari keyboard, so they pass criterion 4. But they are editing keys: TAB moves the cursor, ESC changes the next key, and BACK SPACE deletes the character before it. Thus the typed line is not the line of the file, and criterion 9 fails.

## Options

Lower-case letters:

1. Type them exactly, as now. A file with lower-case keywords gives a BASIC error, as on a real computer.
2. Type each lower-case letter as upper case, except in strings (between `"` characters) and after `REM`. Most files from the internet then work. Criterion 9 changes.

Control characters:

3. Reject them. Criterion 4 changes to: "A file with a character that has no key on the Atari keyboard, or with a control character (TAB, ESC, BACK SPACE), gives exit code 2 before the machine starts, and a message that names the file, the line number and the character."
4. Type ESC and then the key, so that the ATASCII graphic character shows. This maps ASCII codes to ATASCII codes in a way that the file does not state.

## Recommendation

Options 1 and 3. They keep criterion 9 simple: the program is the file, and a file that cannot be typed exactly is an error with a clear message.

## Decision

Not decided.
