# OI-056: SIOV shortcut in the frontend

## Question

Is the SIOV shortcut (REQ-623) on or off in the window, and can the user change it?

## Context

REQ-623 gives the shortcut: the emulator does an OS disk request at once, so a disk loads in much less time. The machine has the setting (`MachineConfig.fast_sio`, `Machine::set_fast_sio`), and the tests use it. No requirement says which value the frontend uses. The frontend now leaves it off, so a disk loads at the real speed of 19,200 baud: a 90 KB disk takes more than one minute.

The shortcut works only for programs that load through the OS routine SIOV. A program with its own disk loader, or a copy protection that measures the timing, loads at the real speed or can fail with the shortcut on.

## Options

1. Off, with no option. Every disk loads at the real speed.
2. On by default, and an option `--no-fast-sio` turns it off.
3. Off by default, and an option `--fast-sio` turns it on.
4. Turbo while the drive transfers data (as REQ-082 for the tape), with the shortcut off. Every loader works, and the load time depends on the host speed.

## Recommendation

Option 4, as for the tape (OI-051). It keeps the emulated machine exact for each loader. Option 2 is faster for programs that use SIOV, and the user can add it later.

## Decision

Decided on 2026-11-21: options 2 and 4 together, the same rules as the tape. The user asked that the disk and the cassette behave the same, and that the lead answers a disk item from the tape decisions.

- The tape has the shortcut on by default, and `--no-fast-tape` turns it off (REQ-644, REQ-091). The disk has the SIOV shortcut on by default, and `--no-fast-disk` turns it off (REQ-094).
- The tape loads in turbo while the motor runs (OI-051, REQ-082). The disk loads in turbo while the drive transfers data (REQ-095), so a loader that does not use SIOV also loads fast.
