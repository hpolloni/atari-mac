# OI-051: Tape load speed

## Question

Does the emulator load a tape at real-time speed only, or does it make the load shorter for the user?

## Context

HRM C.1: "The standard bit rate for a tape is 600 baud". A record of 132 bytes takes 2.2 s, and a file has a 20-second leader (FAQ 7.1.6). A game of 32 KB has approximately 256 records. With the gaps between the records, the load takes more than 10 minutes at real-time speed.

REQ-623 (SIOV shortcut) does not handle the cassette: the OS sends the cassette requests to its own cassette code, not to the SIO bus (HRM 9.1: "Device $5F is special as it is a virtual device used by the OS to represent the cassette device, intercepted by the SIO routines and routed to special cassette code"). OI-046 asks if the code is `DDEVIC` = `$5F` or `$60`.

REQ-080 criterion 7 already runs the emulator with no real-time frame pacing (turbo) while it types a BASIC program.

## Options

1. Real-time speed only.
2. Turbo while the motor runs: the window runs with no frame pacing while the motor line is low, and shows a frame at least every 100 ms of host time (as REQ-080 criterion 7). The emulated machine stays exact to the cycle, so all loaders work.
3. A cassette shortcut: the emulator does an OS cassette read request at once (as REQ-623 for the disk). This works only for programs that load through the OS, and it depends on OI-046 and on the OS ROM.
4. Options 2 and 3.

## Recommendation

Option 2. It works for each loader, also for games with their own tape loader, and it does not change the emulated machine. It needs no decision on OI-046. The load time then depends on the host speed.

## Decision

Decided by the user on 2026-11-20: option 2. The window runs with no frame pacing while the motor line is low, and shows a frame at least every 100 ms of host time. REQ-082 states the rule.
