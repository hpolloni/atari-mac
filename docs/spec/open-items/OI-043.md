# OI-043: NMIEN disable deadline for the VBI

## Question

On which cycle must a write of `$00` to `NMIEN` occur to block the VBI of the same line?

## Context

HRM 4.8: "NMIEN must be written by cycle 7 to enable an interrupt and by cycle 8 in order to disable it." REQ-334 criterion 5 follows the HRM.

ACID800 `antic_nmist` disables the VBI on scan line 248. A teammate counted the write cycles after `WSYNC`. A write on cycle 6 blocks the VBI. A write on cycle 7 does not block it (the test message is "VBI was deactivated by write to NMIEN on cycle 6.", and the test expects the VBI). With the same counting, the enable cases (cycle 7 enables, cycle 8 does not) and the `NMIST` reads of the test agree with the HRM. So in the test, an enable on cycle 7 works, but a disable on cycle 7 does not. The HRM rule cannot give that result. The cycle count is the teammate's reading of the test source.

## Options

1. Keep the HRM rule (disable by cycle 8).
2. Follow ACID800: enable by cycle 7, disable by cycle 6.
3. Record the conflict, and decide after a test on real hardware or a second reading of the test.

## Recommendation

Option 3. The difference is one cycle, and the evidence is one reading of one test.

## Decision

Not decided.
