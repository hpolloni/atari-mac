# OI-017: NMI start cycle contract with the CPU

## Question

Does the CPU accept that ANTIC asserts the NMI line on cycle 9 (cycle 10 after an `NMIEN` write on cycle 7)?

## Context

The ANTIC design needs this to satisfy three HRM statements about `NMIEN` deadlines. The CPU design polls the NMI line in the real 6502 cycles.

## Options

1. Accept the ANTIC contract, and add a joint test that checks the NMI start cycles of REQ-334 with the real CPU.

## Recommendation

Option 1. The joint test goes into SLICE-01.

## Context added on 2026-11-19 (the joint test)

The decision of 2026-11-19 said that the contracts agree, and asked for a joint test. The
WP-5 integration measured with the real CPU and ANTIC:

1. ANTIC sets `out.nmi` on cycle 9. The CPU needs 2 more cycles to recognize it (REQ-118),
   so the earliest NMI sequence starts on cycle 11.
2. A `NOP` that starts on cycle 8 gives an NMI sequence on cycle 12. REQ-334 criterion 2
   requires cycle 10.
3. A `BRK` on cycle 5 of line 248 loses the NMI. HRM 4.8 and REQ-335 criterion 2 say that the
   NMI takes over the `BRK` sequence.
4. With `out.nmi` on cycle 8, cases 2 and 3 pass, but a disable write on cycle 8 no longer
   stops the NMI (REQ-334 criterion 5).

So the contracts do not agree, and the earlier decision is withdrawn. REQ-334 and REQ-335
are not in SLICE-01.

## Decision

Not decided.
