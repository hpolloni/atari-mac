# OI-017: NMI start cycle contract with the CPU

| Field | Value |
| --- | --- |
| Status | Decided |
| Area | ANTIC, CPU |
| Affects | REQ-116, REQ-334; antic.md; cpu.md |
| Raised | 2026-11-19, specification review |

## Question

Does the CPU accept that ANTIC asserts the NMI line on cycle 9 (cycle 10 after an `NMIEN` write on cycle 7)?

## Context

The ANTIC design needs this to satisfy three HRM statements about `NMIEN` deadlines. The CPU design polls the NMI line in the real 6502 cycles.

## Options

1. Accept the ANTIC contract, and add a joint test that checks the NMI start cycles of REQ-334 with the real CPU.

## Recommendation

Option 1. The joint test goes into SLICE-01.

## Decision

Decided on 2026-11-19 by the lead. The contracts agree:

1. ANTIC sets `CycleOutput::nmi` on one cycle (cycle 9, or cycle 10 after an `NMIEN` write on cycle 7).
2. The machine calls `cpu.set_nmi(out.nmi)` in each cycle (`system.md`, "Timing", step 3).
3. The CPU latches the edge, also in a halted cycle, and samples it at the end of the next cycle in which it runs (`cpu.md`, "Interrupt lines and polling").

A paper check cannot prove the exact NMI start cycles of REQ-334 with the real CPU polling. So a joint test is added: `crates/harness/tests/antic_cpu.rs` `nmi_start_cycles_with_real_cpu`. It is in SLICE-01, because SLICE-01 includes the VBI.

Changed: `antic.md` (test plan), `test-harness.md` (test suites).
