# REQ-127: Halted cycles and interrupt recognition

| Field | Value |
| --- | --- |
| Status | Draft |
| Priority | Should |
| Area | CPU (6502C) |
| Source | HRM 5.7 Interrupts (Interrupt timing); HRM 4.9 WSYNC (Interrupt delays due to WSYNC) |
| Verification | Test |
| Depends on | REQ-118, REQ-125, REQ-126 |

## Requirement

The emulator shall count only the cycles in which the CPU runs toward the 2-cycle interrupt recognition delay of REQ-118.

## Rationale

The IRQ delay is a number of unhalted cycles, and it becomes longer when ANTIC halts the CPU (HRM 5.7). The CPU cannot respond to an interrupt until the `WSYNC` stop ends (HRM 4.9).

## Acceptance criteria

1. A `NOP` starts in cycle N. The NMI line goes high in cycle N. ANTIC halts the CPU in cycles N+1 to N+8. The second cycle of the `NOP` is cycle N+9. The NMI sequence starts in cycle N+10.
2. As in criterion 1, but the NMI line goes high in cycle N+1, a halted cycle. The edge is not lost. The next `NOP` runs in cycles N+10 and N+11. The NMI sequence starts in cycle N+12.
3. `STA $D40A` runs in cycles C to C+3. RDY is low in cycles C+4 to C+20, so the CPU stops on the opcode fetch of the next instruction (`NOP`). The NMI line goes high in cycle C+10. The `NOP` runs in cycles C+21 and C+22. The NMI sequence starts in cycle C+23.
4. `STA $D40A` runs in cycles C to C+3. The NMI line goes high in cycle C+1. RDY is low in cycles C+4 to C+20. The CPU repeats the first read of the NMI sequence in cycles C+4 to C+21. The NMI sequence ends in cycle C+27. Cycle C+28 fetches the first opcode of the NMI handler.

## Notes

The HRM states the unhalted cycle rule for IRQ. The emulator uses the same rule for NMI and for cycles stopped by RDY (project decision). The CPU keeps an NMI edge that occurs in a halted cycle, so that no edge is lost.
