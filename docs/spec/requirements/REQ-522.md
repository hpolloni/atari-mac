# REQ-522: BREAK key

## Requirement

When the keyboard scan detects that the BREAK key changed from up to down and `IRQEN` bit 7 is 1, the emulator shall set `IRQST` bit 7 to 0.

## Rationale

The OS uses the BREAK IRQ to stop BASIC programs and I/O operations.

## Acceptance criteria

In criteria 1-6, `SKCTL` = `$03`, and `IRQEN` = `$80` unless the criterion gives a different value.

1. When BREAK goes down on cycle B, `IRQST` bit 7 reads 0 within 65 x 114 cycles after B.
2. After criterion 1, while BREAK stays down, a write of `IRQEN` = `$00` and then `IRQEN` = `$80` makes `IRQST` bit 7 read 1 for the next 300 x 114 cycles.
3. With `IRQEN` = `$00`, BREAK goes down and stays down. After 100 x 114 cycles, a write of `IRQEN` = `$80` makes `IRQST` bit 7 read 1 for the next 300 x 114 cycles.
4. After criterion 1, the test clears `IRQST` bit 7 (`IRQEN` = `$00`, then `$80`). BREAK goes up for 100 x 114 cycles and then down again. `IRQST` bit 7 reads 0 within 65 x 114 cycles after the second down.
5. BREAK down for 200 x 114 cycles and up for 200 x 114 cycles does not change `KBCODE`, `SKSTAT` bit 2 or `SKSTAT` bit 6.
6. With `SKCTL` = `$01`, BREAK down for 300 x 114 cycles keeps `IRQST` bit 7 at 1.
7. With `SKCTL` = `$02` (debounce off), criterion 1 gives the same result.

## Notes

The HRM states that the scan detects BREAK together with scan code `$30`. Software cannot read the state of the BREAK key.
