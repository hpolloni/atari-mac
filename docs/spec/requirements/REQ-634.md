# REQ-634: Read Percom block

## Requirement

In reply to Read Percom block (`$4E`), the disk drive shall send Complete and a 12-byte block that gives the geometry of the inserted image.

| Image | Block |
| --- | --- |
| SD (720 x 128) | `28 00 00 12 00 00 00 80 FF 00 00 00` |
| ED (1040 x 128) | `28 00 00 1A 00 04 00 80 FF 00 00 00` |
| DD (720 x 256) | `28 00 00 12 00 04 01 00 FF 00 00 00` |
| Other N x S | `01 00 hi(N) lo(N) 00 d hi(S) lo(S) FF 00 00 00`, with d = `$00` for S = 128 and `$04` for S = 256 |

## Rationale

DOS versions that support double density, for example SpartaDOS and MyDOS, read the Percom block to find the disk geometry.

## Acceptance criteria

In each criterion, the drive sends `41`, `43`, the 12-byte block and the checksum of the block (REQ-616).

1. For the SD, ED and DD images of REQ-625, the block is the block in the table for that image.
2. For an image of 16384 sectors of 128 bytes, the block is `01 00 40 00 00 00 00 80 FF 00 00 00`.
3. For an image of 1440 sectors of 256 bytes, the block is `01 00 05 A0 00 04 01 00 FF 00 00 00`.
4. Read Percom block with AUX1 = AUX2 = `$FF` gives the same block as with AUX1 = AUX2 = `$00`.

## Notes

The block fields are: tracks, step rate, sectors per track (MSB first), sides minus 1, density, sector size (MSB first), drive present, ACIA byte, and two unused bytes. The HRM states that two-byte fields are big-endian.

The step rate (`$00`) and the "drive present" byte (`$FF`) are the Happy 1050 values in HRM Table 47. The HRM states that arbitrary geometries often show a single track.

FAQ 3.2.6 says that byte 8 is translation control: bit 6 is always 1 (drive present), bit 7 = 1 selects 40-track I/O on an 80-track drive, bit 1 = 1 makes sectors 1-3 full size, and bit 0 = 1 numbers the sectors from 0. The HRM says that byte 8 is drive present, with any value other than 0 for a drive that is present. This requirement follows the HRM (`$FF`, the Happy 1050 value of HRM Table 47).
