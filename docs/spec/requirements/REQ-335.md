# REQ-335: NMI lost after an IRQ on cycle 4

## Requirement

The emulator shall lose the NMI of a scan line if the CPU starts an IRQ sequence (or a `BRK` sequence) on exactly cycle 4 of that scan line.

## Rationale

On hardware, DLIs during SIO transfers sometimes fail and the screen shows glitches. The emulator then shows the same glitches.

## Acceptance criteria

1. With `DMACTL` = `$00` and `NMIEN` = `$40`, a `BRK` instruction has its opcode fetch on cycle 4 of scan line 248. The CPU runs the `BRK` handler, and the NMI handler does not run in that frame. `NMIST` bit 6 reads 1 from cycle 7 of scan line 248.
2. In the same setup, with the `BRK` opcode fetch on cycle 3 or on cycle 5, the NMI handler runs once in that frame.
3. Removed (OI-017): the CPU rule of REQ-122 loses the NMI, so ANTIC has no separate mechanism. The number is kept, so that the numbers of the other criteria do not change.

## Notes

This needs information from the CPU: the cycle where an interrupt sequence starts. The HRM says the cause is probably a too-short NMI pulse from ANTIC. A normal 7-cycle instruction cannot cause this.
