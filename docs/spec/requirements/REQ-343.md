# REQ-343: Line buffer persistence

| Field | Value |
| --- | --- |
| Status | Draft |
| Priority | Could |
| Area | ANTIC |
| Source | HRM 4.11 Playfield DMA (Line buffering, Loading the line buffer, Line buffer addressing) |
| Verification | Test |
| Depends on | REQ-312 |

## Requirement

The emulator shall keep a 48-byte line buffer that ANTIC never clears, and shall show its contents on scan lines where the mode line uses buffered data but no playfield DMA loaded it.

## Rationale

Demos fill the screen with little or no playfield DMA by toggling playfield DMA and extending mode lines with vertical scrolling.

## Acceptance criteria

1. A normal-width mode E line loads 40 bytes into the line buffer. After 8 blank scan lines (`$70`), a jump (`$01`) and a vertical blank, the debug state shows the same line buffer bytes 0-39.
2. A wide mode E line loads bytes W0-W47 into the line buffer. A narrow mode E line then loads bytes 0-31, and bytes 32-47 still hold W32-W47. A normal mode E line then loads bytes 0-39, and bytes 40-47 still hold W40-W47.
3. The line buffer holds bytes B0-B19 from an earlier normal mode A line. A new mode A line has `DMACTL` = `$20` on its first scan line, and the test writes `$22` to `DMACTL` on cycle 110 of that scan line. Scan lines 2-4 show the codes of B0-B19, not of the new screen memory.
4. A normal mode E line loads B0-B39. A mode 8 line follows, with `DMACTL` = `$20` on its first scan line and `$22` from cycle 110 of that scan line. Scan lines 2-8 show B0-B9 as mode 8 data: byte k starts at position `$30 + 16k`.
5. A normal mode A line loads B0-B19. The test writes `$21` to `DMACTL` on cycle 110 of its first scan line. On scan line 2, B0 starts at position `$40`, and B0-B15 fill positions `$40-$BF`.
