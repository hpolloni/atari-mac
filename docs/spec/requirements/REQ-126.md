# REQ-126: CPU stop by RDY

| Field | Value |
| --- | --- |
| Status | Draft |
| Priority | Must |
| Area | CPU (6502C) |
| Source | HRM 4.9 WSYNC (Interrupt delays due to WSYNC, Read-modify-write instructions, Bus activity during WSYNC); HRM 2.3 Memory system (Floating data bus) |
| Verification | Test |
| Depends on | REQ-101 |

## Requirement

While RDY is low, the emulator shall repeat the current CPU read cycle in each cycle, and shall execute CPU write cycles normally.

## Rationale

A write to `WSYNC` pulls RDY low. The CPU then repeats its current read cycle until RDY goes high (HRM 4.9). The repeated reads put data on the bus and can touch read-sensitive hardware. `INC WSYNC` needs the write cycle behavior.

## Acceptance criteria

1. RDY is low in cycles C to C+9. Cycle C is the opcode fetch of a `NOP` at `$2000`. The CPU reads `$2000` in each of cycles C to C+10 (11 reads). The second cycle of the `NOP` is cycle C+11.
2. `INC $D40A` starts in cycle C. It writes the old value in cycle C+4. RDY is low in cycles C+5 to C+20. The write of the new value occurs in cycle C+5. The opcode fetch of the next instruction repeats in cycles C+6 to C+21. The second cycle of that instruction is cycle C+22.
3. `STA $0600` writes in cycle C. RDY is low in cycles C to C+9. The write occurs in cycle C. The opcode fetch of the next instruction repeats in cycles C+1 to C+10.
4. During the repeated reads of criteria 1 to 3, `A`, `X`, `Y`, `S`, `P` and `PC` do not change.

## Notes

HRM 4.9 is in the ANTIC chapter. This requirement covers only the CPU side. The ANTIC timing of RDY is in the REQ-300 range.
