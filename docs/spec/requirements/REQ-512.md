# REQ-512: Noise delay between channels

## Requirement

The emulator shall give each noise bit to channels 1, 2, 3 and 4 in that order, one cycle apart.

## Rationale

The delay prevents two channels with the same timing from playing the same noise. Some demos depend on the exact noise pattern.

## Acceptance criteria

"Gets bit i" means that the channel flip-flop takes bit i of the pattern on a fire. The test checks each criterion for 30 consecutive fires.

1. With `AUDCTL` = `$00`, `AUDF1` = `AUDF2` = `$00`, `AUDC1` = `AUDC2` = `$CF` and an `STIMER` write, timers 1 and 2 fire on the same cycles. When channel 1 gets bit i of the 4-bit pattern of REQ-513, channel 2 gets bit i - 1 (modulo 15) on the same fire.
2. With `AUDCTL` = `$60`, `AUDF1` = `AUDF3` = `$00`, `AUDC1` = `AUDC3` = `$CF` and an `STIMER` write, when channel 1 gets bit i of the 4-bit pattern, channel 3 gets bit i - 2 (modulo 15) on the same fire.
3. With `AUDCTL` = `$80`, `AUDF1` = `AUDF4` = `$00`, `AUDC1` = `AUDC4` = `$8F` and an `STIMER` write, when channel 1 gets bit i of the 9-bit pattern, channel 4 gets bit i - 3 (modulo 511) on the same fire. The 9-bit pattern is the inverse of `RANDOM` bit 0 on consecutive cycles.
4. With the setup of criterion 3, the bit that channel 1 gets on a fire on cycle C is the inverse of `RANDOM` bit 0 on cycle C - 1.

## Notes

The HRM states that the 9/17-bit noise to the channels comes from the right end of `RANDOM`. So the CPU can see each noise bit before the audio circuits get it. The HRM does not give the number of cycles. The delay of 1 cycle in criterion 4 is a project decision (`docs/design/pokey.md`, "Noise generators").
