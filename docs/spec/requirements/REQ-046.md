# REQ-046: Valid source citations

## Requirement

The `source` of each requirement shall be either a list of citations of frozen references, or `Project decision`, and each cited reference shall have a registry entry and a section index in `docs/spec/references/`.

## Rationale

A wrong section number or a reference that can change sends the reader to the wrong place.

## Acceptance criteria

1. Each reference has a registry entry `docs/spec/references/<ID>.md` with YAML frontmatter: `id`, `title`, `edition`, `author`, `license` (the license text or `none found`), `storage` (`commit` or `pin`), `url`, `sha256` and `file`. `<ID>` has only upper-case letters, digits and `-`, and is the same as `id`. The body has a `## License` section that quotes the license text of the reference, or says that the reference has no license text.
2. Each reference has a section index `docs/spec/references/<ID>.sections.txt`: one section per line, `<key><TAB><title>`. A key has no spaces. Lines that start with `#` are comments. A reference that has no sections has an index with no section lines.
3. A source with citations is a list of citations, separated by `; `. Each citation starts with a registry ID. When the index of that reference has section lines, the second word of the citation is a key of that index, and the citation can continue with the section title. When the index has no section lines, the citation is only the ID.
4. When a source cites `HRM` and other references, the first citation is an `HRM` citation.
5. A source that is not `Project decision` and has a citation with an unknown ID, an unknown key, or no key where the index has keys makes the check fail.
6. A requirement with the source `Project decision` and no `Notes` section makes the check fail.
7. A registry entry with the storage `commit` has its `file` in `reference/` in git, and the SHA-256 of that file is the `sha256` of the entry. A different checksum or a missing file makes the check fail.
8. A registry entry with the storage `pin` has its `file` in `reference/pinned/`, which git ignores. Its `url` contains a commit hash, an archive.org item path or a Wayback Machine timestamp.

## Notes

Project decision (OI-041). The HRM is the main source. When another reference does not agree with the HRM, the requirement follows the HRM, cites both references, and states the difference in its `Notes` section.

The checks use only the registry, the section indices and the committed files, so they do not need the pinned files.
