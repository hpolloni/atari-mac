# REQ-402: Power-on and reset state

## Requirement

The emulator shall set all GTIA write registers, collision latches, trigger latches and P/M shift registers to 0 at power-on, and shall not change them at a system reset.

## Rationale

The HRM states that the power-on values of GTIA are not guaranteed and that software must clear the registers. A fixed power-on state makes runs repeatable. The HRM also states that a reset does not affect GTIA.

## Acceptance criteria

1. After power-on and before any GTIA write, `M0PF-P3PL` (`$D000-$D00F`) read `$00`.
2. After power-on, with no console key pressed and no `CONSOL` write, `CONSOL` reads `$0F`.
3. After power-on, with all trigger inputs inactive, a write of `$04` to `GRACTL` gives `$01` from `TRIG0-TRIG3` (the trigger latches are clear).
4. After power-on and before any GTIA write, all 92160 bytes of the first complete frame are `$00`, for any AN codes.
5. After power-on, a write of `$FF` to `GRAFP0-GRAFP3` and `GRAFM` and of `$0E` to `COLPM0-COLPM3` gives no `$0E` byte in the next frame. All position registers are 0, so the objects shift out in horizontal blank.
6. A collision bit that is set before a press of the RESET key still reads 1 after it, until a write to `HITCLR`.
7. With `COLBK` = `$46` before a press of the RESET key and no GTIA write after it, the background pixels of the next frame are `$46`.

## Notes

Source: project decision. Table 13 lists observed power-on read values, for example `$0E` for `P0PL`. The HRM states that these values are not architecturally guaranteed. The project uses 0 for all state, because the HRM gives no guaranteed value. The RESET key on the 65XE resets the CPU only (system requirements, REQ-2xx).
