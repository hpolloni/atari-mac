# REQ-535: Paddle inputs

## Requirement

The emulator shall let the host set, for each of the inputs `POT0-POT3`, the scan count c at which the input reaches threshold, and shall keep the inputs `POT4-POT7` below threshold. In a scan from empty capacitors, an input with count c shall reach threshold 114 x c + 1 cycles after the `POTGO` write.

## Rationale

The 65XE has two controller ports, with up to four paddles. HRM 7.2 gives the paddle range as 1 (fully counterclockwise) to 228 (fully clockwise).

## Acceptance criteria

In criteria 1-4, the scan is a slow scan with the setup of REQ-534.

1. For each input 0-3, `set_pot(n, c)` makes `POTn` read c after the scan, and `ALLPOT` bit n change to 0 on cycle G + 114 x c + 1, for c = 1, 100 and 227. The test checks input 0 for each of the 114 values of (G - W) modulo 114.
2. `set_pot(0, 228)`, `set_pot(0, 255)`, or no call of `set_pot` for input 0, makes `POT0` read 228 after the scan.
3. `POT4-POT7` read 228 after a slow scan. They read 229 after a scan with `SKCTL` bit 2 = 1 (REQ-536 criterion 1).
4. With `set_pot(0, 200)`, a call of `set_pot(0, 50)` when `POT0` reads 100 makes `ALLPOT` bit 0 read 0 from the next cycle. `POT0` reads 100 or 101 after the scan.

## Notes

The paddle trigger buttons are joystick direction inputs of the PIA. They are not part of POKEY.

HRM 7.2 states that a CX30 paddle reaches a count of 228 at about half of its rotation. The frontend selects how host input maps to the count.

HRM 5.9 states that unconnected inputs do not charge. So an unconnected input stays below threshold and reads 228.

The HRM gives no exact cycle on which an input reaches threshold. The charge time of 114 x c + 1 cycles is a project decision. It gives the count c for each phase of the 15 kHz clock (`docs/design/pokey.md`, "Pot scan").

FAQ 1.15 gives `POT0-POT3` on controller ports 1 and 2 of all machines, and `POT4-POT7` on ports 3 and 4 of the 400 and 800 only.

TRN HW-II.E/Paddles says that the values range from 0 (paddle turned to the right) to 228 (paddle turned counterclockwise). POKEY-SPEC 4 says that a clockwise turn decreases the pot value. HRM 7.2 says that the range is 1 to 228, where 1 is fully counterclockwise and 228 is fully clockwise. This requirement follows the HRM. The requirement does not use the direction, because the frontend maps host input to the count.
