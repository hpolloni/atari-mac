# REQ-526: Serial input

## Requirement

After a start bit on SIO DATA IN, the emulator shall shift in a 10-bit frame, copy the 8 data bits into `SERIN` when it samples the stop bit, and set `IRQST` bit 5 to 0 at that time if `IRQEN` bit 5 is 1.

## Rationale

The OS SIO code receives all data from disk drives and other devices through `SERIN` and the serial input ready interrupt.

## Acceptance criteria

In all criteria, `SKCTL` = `$13`, `AUDCTL` = `$28`, `AUDF3` = `$28`, `AUDF4` = `$00` and `IRQEN` = `$20`, and SIO DATA IN is 1 for at least 1000 cycles before the frame. The test sends a frame as levels on SIO DATA IN: a start bit 0, 8 data bits from bit 0 to bit 7, and a stop bit 1, each for 94 cycles. The falling edge of the start bit is on cycle S.

1. A frame for `$43` makes `SERIN` read `$43` from the cycle on which `IRQST` bit 5 goes to 0.
2. `IRQST` bit 5 reads 0 first on a cycle from S+885 to S+901 (19 timer periods = 893 cycles, +/- 8 cycles).
3. `SKSTAT` bit 1 reads 1 on each cycle before S+39, 0 on each cycle from S+55 to S+885, and 1 from cycle S+901.
4. Two instances receive the frame of criterion 1. One instance also reads `SERIN` on each cycle. The reads of all registers (with `peek`) of the two instances are the same on each cycle.
5. The test sends the 256 bytes `$00` to `$FF` back-to-back: each start bit begins directly after the stop bit of the byte before. On each cycle on which `IRQST` bit 5 goes to 0, the test reads `SERIN` and writes `IRQEN` = `$00` and then `IRQEN` = `$20`. The 256 values read are `$00` to `$FF` in order. At the end, `SKSTAT` bits 5 and 7 read 1.
6. With `IRQEN` = `$00`, the frame of criterion 1 makes `SERIN` read `$43`, and `IRQST` bit 5 reads 1 on each cycle.

## Notes

The emulator receives the level of SIO DATA IN from the SIO bus model (REQ-600 and later). The +/- 8 cycle tolerance in criterion 2 is a project decision for the test. The HRM does not give the delay from the start edge to the timer start.

HRM 14.4 states that a read of `SERIN` "clears the internal data-ready state". HRM 5.6 states that the read has no side effects. Both state that only `IRQST` bit 5 controls the overrun detection. The emulator follows HRM 5.6.

TRN HW-II.C/Serial-Input and POKEY-SPEC 7 state that the overrun occurs when `IRQST` bit 5 is not reset before the next byte completes. They do not give a side effect of a `SERIN` read. ACID800 pokey_skstat checks that `SKSTAT` bit 1 reads 1 while the input is idle and 0 while a byte is received.
