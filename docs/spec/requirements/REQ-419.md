# REQ-419: P/M shift state machine and size changes

## Requirement

The emulator shall step each object's 2-bit shift state at each color clock as `state' = (state + 1) AND size`, shift one bit at each step to state `%00`, set state `%00` at each load, and apply a new size to the current shift state, with no reload, from the color clock where the size write takes effect (REQ-434).

## Rationale

This state machine gives the HRM results for size changes in the middle of an image, including the lockup with size code `%10`.

## Acceptance criteria

1. For each of the 20 rows of HRM Table 15, a unit test sets the original size, puts the object in the shift state of the last "before" column of the row, and writes the new size. The next four shift states are the four "after" values of the row. The shift register shifts one bit at each step to state `%00`.
2. With `GRAFP0` = `$80`, `HPOSP0` = `$40`, `SIZEP0` = `$01` and a write of `$02` to `SIZEP0` that takes effect at HPOS `$41` (cycle 31, REQ-434), HPOS `$40-$DD` of that scanline and HPOS `$22-$3F` of the next scanline show `COLPM0`.
3. With `GRAFP0` = `$FF` and `HPOSP0` = `$40`, a write to `SIZEP0` that takes effect at HPOS `$81` (after the image; a `SIZEP0` write takes effect on an odd HPOS, REQ-434) from `$00` to `$01`, from `$00` to `$03`, from `$01` to `$00` and from `$03` to `$00` gives the same frame buffer row as no write.

## Notes

The HRM states that changes between double and quadruple width are slightly erratic on real hardware (HRM 6.10). The emulator uses the state machine only. In the two rows of Table 15 with the change "2x to 1x*", the last "before" value cannot come from the original size. The test starts from that value as given.
