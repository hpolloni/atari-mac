# REQ-119: Interrupt delay after CLI and PLP

## Requirement

The emulator shall service a pending IRQ after the instruction that follows a `CLI` or `PLP` that clears `I`, and directly after an `RTI` that clears `I`.

## Rationale

The OS and many programs use `CLI` to start IRQ service. The instruction after which the IRQ occurs changes timing and stack contents.

## Acceptance criteria

1. Start: `I` = 1, the IRQ line asserted, `CLI` at `$0200`, `NOP` at `$0201` and `$0202`. The `CLI` and the `NOP` at `$0201` execute. Then the IRQ sequence starts. It pushes the return address `$0202`.
2. Start: `I` = 1, the IRQ line asserted, `S` = `$FE`, `$01FF` = `$20`, `PLP` at `$0200`, `NOP` at `$0201` and `$0202`. The `PLP` and the `NOP` at `$0201` execute. Then the IRQ sequence starts. It pushes the return address `$0202`.
3. Start: `I` = 1, the IRQ line asserted, `S` = `$FC`, `$01FD` = `$20`, `$01FE` = `$00`, `$01FF` = `$04`, `RTI` at `$0200`, `NOP` at `$0400`. The IRQ sequence starts directly after the `RTI`. It pushes the return address `$0400`. The `NOP` at `$0400` does not execute before the sequence.
