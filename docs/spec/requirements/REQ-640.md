# REQ-640: CAS image errors

## Requirement

The emulator shall reject a CAS image that is shorter than one chunk header, that does not start with a `FUJI` chunk, that has a chunk that goes past the end of the file, a chunk type that the emulator does not support, a `baud` chunk with the baud rate 0, an `fsk ` chunk with an odd data length, or no `data` or `fsk ` chunk, and shall report which of these errors occurred.

## Rationale

A bad image must not crash the emulator (REQ-016). An error that names the chunk offset helps the user to find the defect in the file.

## Acceptance criteria

The test files start from the file T of REQ-639 (201 bytes). Each criterion changes one thing, unless it states more changes.

1. The first 7 bytes of T give the error `CasHeader`.
2. T with bytes 0-3 changed to `46 55 4A 4A` (`FUJJ`) gives the error `CasSignature`. The file of bytes 12-200 of T (it starts with the `baud` chunk) also gives `CasSignature`.
3. The first 100 bytes of T give the error `CasTruncated { offset: 20 }`. (The `data` chunk at offset 20 needs 140 bytes.)
4. T with the 5 bytes `64 61 74 61 00` added after it gives the error `CasTruncated { offset: 201 }`. (The chunk header is not complete.)
5. T with bytes 160-163 changed to `70 77 6D 73` (`pwms`) gives the error `CasChunkType { offset: 160, chunk_type: *b"pwms" }`. The same is true for `pwmc`, `pwmd`, `pwml` and `xyzw`.
6. T with bytes 166-167 changed to `00 00` (baud rate 0) gives the error `CasBaud { offset: 160 }`.
7. T with bytes 183-184 changed to `05 00` (`fsk ` data length 5) gives the error `CasFskLength { offset: 179, length: 5 }`.
8. The first 12 bytes of T (the `FUJI` chunk only) give the error `CasEmpty`. T with bytes 20-178 removed (no `data` chunk, but the `fsk ` chunk) loads with no error.
9. The emulator checks the errors in this order and reports the first error: `CasHeader`, `CasSignature`, then the chunks in file order, and for each chunk `CasTruncated`, `CasChunkType`, `CasBaud`, `CasFskLength`; and then `CasEmpty`. Thus: a file of 7 bytes that starts with `46 55 4A 4A` gives `CasHeader`. The first 165 bytes of T with bytes 160-163 changed to `pwms` give `CasTruncated { offset: 160 }`. T with bytes 160-163 changed to `pwms` and bytes 183-184 changed to `05 00` gives `CasChunkType { offset: 160, chunk_type: *b"pwms" }`.

## Notes

The error rules are a project decision. CAS-FMT gives the 8-byte chunk header, the rule that the file must begin with a `FUJI` chunk, and the `fsk ` data as `chunk_length/2` 16-bit numbers. CAS-FMT does not give a rule for a baud rate of 0 or for an odd `fsk ` length.

The rejection of the turbo chunk types `pwms`, `pwmc`, `pwmd` and `pwml` and of other chunk types is the recommended option of OI-048, which is open. If the user selects a different option, criterion 5 changes.

A `baud` chunk with a data length that is not 0 loads with no error: the emulator ignores its data bytes. CAS-FMT says that the length "is always 0". This is a project decision.

The HRM does not describe the CAS format.
