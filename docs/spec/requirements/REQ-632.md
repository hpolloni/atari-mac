# REQ-632: Format commands

| Field | Value |
| --- | --- |
| Status | Draft |
| Priority | Must |
| Area | Media |
| Source | HRM 10.2 Basic protocol (Format ($21)); HRM 10.15 1050 disk drive (Format Medium Density command); HRM 10.3 Extended protocols (Double density, Percom block standard); HRM 10.5 Timing (Table 52) |
| Verification | Test |
| Depends on | REQ-619, REQ-625 |

## Requirement

In reply to a format command on a write-enabled image, the disk drive shall replace the image with an image of the geometry in the table with all bytes `$00`, send Complete, and send a data frame of the new sector size with all bytes `$FF`.

| Command | New geometry |
| --- | --- |
| Format `$21` | SD: 720 sectors of 128 bytes. DD: 720 sectors of 256 bytes, if a Write Percom block (REQ-635) selected 256-byte sectors after the image was inserted. |
| Format medium `$22` | ED: 1040 sectors of 128 bytes |

## Rationale

DOS formats new disks with these commands. DOS 2.5 uses `$22` for 130 KB disks. The returned frame is the list of bad sectors, terminated by `$FFFF`. An image has no bad sectors.

## Acceptance criteria

The test images are the SD, ED and DD files of REQ-625 (data byte `i` holds `i & $FF`), write enabled.

1. Format `$21` on the ED image: the drive sends `41`, `43`, 128 bytes of `$FF` and `FF`. The image then has 720 sectors of 128 bytes, and each sector reads as 128 bytes of `$00`.
2. Format `$22` on the SD image: the drive sends `41`, `43`, 128 bytes of `$FF` and `FF`. The image then has 1040 sectors of 128 bytes, each sector reads as 128 bytes of `$00`, and Status gives byte 0 = `$80`.
3. Format `$21` on the DD image, with no Write Percom block after the insertion: the image then has 720 sectors of 128 bytes (SD).
4. Write Percom block with the DD block of REQ-634, and then Format `$21` on the SD image: the drive sends `41`, `43`, 256 bytes of `$FF` and `FF`. The image then has 720 sectors, sectors 1-3 read as 128 bytes of `$00`, and sectors 4-720 read as 256 bytes of `$00`.
5. Before a format, the image reports no change. After the format of criterion 1, the image reports a change (REQ-637).

## Notes

The HRM states that a format fills all sectors with `$00` and returns a sector-sized list of bad sectors terminated by `$FFFF`. An image has no bad sectors, so the list starts with `$FF $FF`. The bytes after `$FF $FF` in the frame are `$FF`. This is a project decision.

A format of an image changes its size. The frontend saves the new size (REQ-637).
