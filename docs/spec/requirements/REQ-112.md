# REQ-112: Unstable undocumented opcodes

| Field | Value |
| --- | --- |
| Status | Draft |

## Requirement

The emulator shall execute the unstable opcodes `ANE` ($8B), `LXA` ($AB), `SHA` ($93, $9F), `SHX` ($9E), `SHY` ($9C) and `SHS` ($9B) with the results of the SingleStepTests 6502 suite.

## Rationale

The HRM states that these opcodes do not operate reliably on all CPUs. A fixed and tested behavior makes the emulator deterministic. Few programs use these opcodes.

## Acceptance criteria

1. The test `single_step_undocumented_unstable` runs all SingleStepTests 6502 cases of `$8B`, `$AB`, `$93`, `$9F`, `$9E`, `$9C` and `$9B`. The final registers, the RAM bytes and the `cycles` list agree with the file.
2. Start: `X` = `$0F`, `Y` = `$01`. `SHX $2000,Y` (`$9E`) writes `$01` (`$0F` AND `$21`) to `$2001`.
3. Start: `X` = `$0F`, `Y` = `$20`. `SHX $20F0,Y` (`$9E`) writes `$01` to `$0110`. The page crossing replaces the high byte `$21` of the address with the value `$01`.
4. Start: `A` = `$F0`, `X` = `$3C`, `Y` = `$01`. `SHS $2000,Y` (`$9B`) sets `S` = `$30` and writes `$20` (`$30` AND `$21`) to `$2001`.

## Notes

The exact formulas are a project decision. The HRM says that `SHA` $93 uses the high byte of the base address. The SingleStepTests data uses the high byte + 1 for $93 and $9F. The HRM reports that `LXA` on an Atari 800 loads the immediate value without the AND. The SingleStepTests data uses `(A OR $EE) AND imm` for `LXA` and `(A OR $EE) AND X AND imm` for `ANE`. The emulator follows the SingleStepTests data. The HRM does not describe `SHY` ($9C). Its behavior also follows the SingleStepTests data.
