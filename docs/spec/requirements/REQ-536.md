# REQ-536: Fast pot scan

## Requirement

When `SKCTL` bit 2 is 1, the emulator shall increment the pot scan counter on each machine cycle, shall make `ALLPOT` read `$00` from 231 cycles after the `POTGO` write, and shall latch 229 into each `POTn` that still follows the counter.

## Rationale

Some programs use fast pot scan as a cycle timer. Some controllers, for example the keyboard controller, are read with fast scans.

## Acceptance criteria

1. With `SKCTL` = `$07` and a `POTGO` write on cycle G, `ALLPOT` bit 4 reads 1 on cycle G+230, and `ALLPOT` reads `$00` from cycle G+231. `POT4` reads 229 from cycle G+230.
2. With `SKCTL` = `$03` for at least 100 cycles (no scan), a write of `SKCTL` = `$07` on cycle F and a `POTGO` write on cycle F+1: `set_pot(0, 1)` gives a `POT0` value from 112 to 114, `set_pot(0, 2)` gives a value from 226 to 228, and `set_pot(0, 3)` gives 229.
3. With `SKCTL` = `$07` and `set_pot(0, 1)`, a first scan latches `POT0` = v. A second `POTGO` write 1000 cycles later keeps `POT0` at v and `ALLPOT` bit 0 at 0 on each cycle of the second scan.
4. With `SKCTL` = `$04` (initialization mode, `SKCTL` bit 2 = 1) and a `POTGO` write on cycle G, `ALLPOT` reads `$00` from cycle G+231 and `POT4` reads 229.

## Notes

In fast mode the counts are 114 times higher for the same charge time. So regular paddles give useless values.

In criterion 2, the dump transistors turn off on the `SKCTL` write (HRM 5.9), one cycle before `POTGO`. The range of 3 values allows for this cycle and for the cycle on which the counter starts.
