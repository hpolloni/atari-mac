# REQ-329: VSCROL write deadlines

## Requirement

The emulator shall use the `VSCROL` value written by cycle 0 for the start row of a mode line, the value written by cycle 108 for the end-of-line check, and the value written by cycle 5 for the DLI decision of that scan line.

## Rationale

The "GTIA 9++" effect writes `VSCROL` twice in the six cycles between the end check and the start check. DLI handlers that change `VSCROL` need the same timing as hardware.

## Acceptance criteria

1. The instruction `$22` follows a `$02` line and starts on scan line N. `VSCROL` = 0 before scan line N. A write of `$05` to `VSCROL` on cycle 0 of scan line N gives the mode line 3 scan lines (rows 5-7). The same write on cycle 1 of scan line N gives the mode line 8 scan lines (rows 0-7).
2. The instruction `$02` follows a `$22` line and starts on scan line N. `VSCROL` = 7. A write of `$03` to `VSCROL` on cycle 108 of scan line N + 3 makes scan line N + 3 the last scan line: the next instruction fetch occurs on scan line N + 4. The same write on cycle 109 of scan line N + 3 does not make scan line N + 3 the last scan line.
3. The instruction `$82` follows a `$22` line and starts on scan line N. `VSCROL` = 7 and `NMIEN` = `$80`. A write of `$03` to `VSCROL` on cycle 5 of scan line N + 3 sets `NMIST` bit 7 and causes an NMI on scan line N + 3, and scan line N + 3 is the last scan line. The same write on cycle 6 of scan line N + 3 causes no DLI on scan line N + 3, and scan line N + 3 is still the last scan line.
4. In the state of criterion 3 but with `VSCROL` = 3, a write of `$07` to `VSCROL` on cycle 5 of scan line N + 3 prevents the DLI on scan line N + 3.

## Notes

HRM 4.7 says "by cycle 108" for the end check. HRM 14.6 says "by cycle 109". HRM Figure 6 puts the end check on the boundary between cycles 108 and 109. This requirement uses cycle 108 and treats HRM 14.6 as an HRM error (OI-013).
