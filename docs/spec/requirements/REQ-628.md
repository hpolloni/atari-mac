# REQ-628: NAK conditions

| Field | Value |
| --- | --- |
| Status | Draft |
| Priority | Must |
| Area | Media |
| Source | HRM 10.2 Basic protocol (Common command conventions); HRM 10.9 810 disk drive (Commands); HRM 9.1 Basic SIO protocol (Negative acknowledge code (NAK)) |
| Verification | Test |
| Depends on | REQ-618, REQ-625 |

## Requirement

The disk drive shall send NAK (`$4E`) for a command code that it does not support, and for a Read, Put or Write command with sector number 0 or a sector number above the sector count of the image.

## Rationale

The drive finds these errors from the command frame alone, so it reports them with NAK. The OS then reports an error to the program at once.

## Acceptance criteria

"Gets NAK" means that the drive sends `4E` and then no byte in the 178,977 machine cycles (100 ms) after the end of the `4E` byte. "Gets ACK" means that the first byte that the drive sends is `41`. Each command frame has device ID `$31` and a valid checksum.

1. With an SD image, each command code from `$00` to `$FF` except `$21`, `$22`, `$4E`, `$4F`, `$50`, `$52`, `$53` and `$57` gets NAK, with AUX1 = `$01` and AUX2 = `$00`.
2. With an SD image, Read with sector 0 (AUX1 = AUX2 = `$00`) gets NAK.
3. Read with sector 721 (AUX1 = `$D1`, AUX2 = `$02`) of an SD image gets NAK. Read with sector 720 (AUX1 = `$D0`, AUX2 = `$02`) gets ACK.
4. Read with sector 1041 (AUX1 = `$11`, AUX2 = `$04`) of an ED image gets NAK. Read with sector 1040 (AUX1 = `$10`, AUX2 = `$04`) gets ACK.
5. Read with sector 721 of a DD image gets NAK. Read with sector 720 gets ACK.
6. Put and Write with sector 0 and with sector 721 of an SD image get NAK. The computer sends no data frame.

## Notes

The sector number is AUX1 (low byte) and AUX2 (high byte).

Command `$3F` gets NAK. The HRM states that `$3F` is the US Doubler "Return High Speed Index" command and also the Type 1 Poll. High-speed transfer is out of scope.

The 810 rev. C accepts `$4F` as Write. This emulator uses `$4F` as Write Percom block (REQ-635).
