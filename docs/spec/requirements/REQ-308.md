# REQ-308: Playfield width and position

## Requirement

The emulator shall select the playfield width with `DMACTL` bits 1-0 and show the playfield at the horizontal positions in the table below.

| `DMACTL` bits 1-0 | Width | Horizontal positions |
| --- | --- | --- |
| `%00` | Disabled | None (background) |
| `%01` | Narrow, 128 color clocks | `$40-$BF` |
| `%10` | Normal, 160 color clocks | `$30-$CF` |
| `%11` | Wide, 192 color clocks | `$20-$DF`, visible only at `$2C-$DD` |

## Rationale

All OS graphics modes use the normal width. Some games use narrow or wide playfields.

## Acceptance criteria

1. With `DMACTL` = `$21` and a mode F line of `$FF` bytes, positions `$40-$BF` have code `%111`, and positions `$22-$3F` and `$C0-$DD` have code `%000`.
2. With `DMACTL` = `$22` and the same line, positions `$30-$CF` have code `%111`, and positions `$22-$2F` and `$D0-$DD` have code `%000`.
3. With `DMACTL` = `$23`, the same line and the value `$FF` on the data bus in every cycle without DMA, positions `$22-$2B` have code `%000` and positions `$2C-$DD` have code `%111`.
4. With `DMACTL` = `$20` and IR = `$0F`, positions `$22-$DD` have code `%000`, and `out.dma` is never `Bitmap`.

## Notes

The horizontal positions are GTIA positions (HRM 6.2). The HRM says that 12 color clocks of a wide playfield are not visible on the left (`$20-$2B`). ANTIC clips 10 of these (`$22-$2B`) and horizontal blank hides 2.
