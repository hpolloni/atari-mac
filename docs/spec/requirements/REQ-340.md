# REQ-340: Player/missile addressing

| Field | Value |
| --- | --- |
| Status | Draft |
| Priority | Must |
| Area | ANTIC |
| Source | HRM 4.13 Player/missile DMA (Vertical resolution, P/M graphics memory layout, P/M DMA timing); HRM 14.6 ANTIC registers (PMBASE) |
| Verification | Test |
| Depends on | REQ-339 |

## Requirement

The emulator shall compute the player/missile fetch addresses from `PMBASE`, `DMACTL` bit 4 and the scan line number Y, as in the table below.

| Data | Two-line (`DMACTL` bit 4 = 0) | One-line (`DMACTL` bit 4 = 1) |
| --- | --- | --- |
| Base | `(PMBASE & $FC) << 8` | `(PMBASE & $F8) << 8` |
| Missiles | Base + `$180` + (Y >> 1) | Base + `$300` + Y |
| Player n (0-3) | Base + `$200` + n × `$80` + (Y >> 1) | Base + `$400` + n × `$100` + Y |

## Rationale

Software puts its P/M data at these addresses. Two-line and one-line resolution use different layouts.

## Acceptance criteria

1. With `PMBASE` = `$30` and `DMACTL` = `$0C` (two-line resolution), on scan line 100, the `Missile` fetch reads `$31B2` (`$3000 + $180 + 50`) and the `Player(2)` fetch reads `$3332`.
2. With `PMBASE` = `$34` and `DMACTL` = `$1C` (one-line resolution), on scan line 100, the `Missile` fetch reads `$3364` and the `Player(0)` fetch reads `$3464`.
3. With `DMACTL` = `$0C`, the `Missile` and `Player` fetches on scan lines 100 and 101 read the same addresses. Fetches occur on both scan lines.
4. With `PMBASE` = `$34`, a write of `$0C` to `DMACTL` after `$1C`, with no new write to `PMBASE`, makes the `Missile` fetch on scan line 100 read `$35B2` (base `$3400`).

## Notes

In the missile byte, bits 1-0 are missile 0 and bits 7-6 are missile 3. GTIA uses this layout.
