# REQ-611: Executable file errors

## Requirement

The emulator shall reject an XEX file that does not start with `$FF $FF` or that has no complete segment, and shall keep only the complete segments before the first defective segment of other files.

## Rationale

Many XEX files have extra bytes at the end, for example padding to a full disk sector. A strict parser would reject files that load on real DOS. A file that has no valid segment cannot run.

## Acceptance criteria

An offset is the index of the first byte of the defective segment header in the file.

1. An empty file gives the error `XexSignature`.
2. The file `FF` gives the error `XexSignature`.
3. The file `00 00 00 20 00 20 11` gives the error `XexSignature`.
4. The file `FF FF` gives the error `XexNoSegment(None)`.
5. The file `FF FF 00 20 FF 1F` gives the error `XexNoSegment(Some(defect))`, with the defect `EndBeforeStart` at offset 2.
6. The file `FF FF 00 20 05 20 11` gives the error `XexNoSegment(Some(defect))`, with the defect `ShortData` at offset 2.
7. The file `FF FF 00 20 00 20 11 00 00 00` loads with one segment (`$2000`, data `11`) and the defect `ShortHeader` at offset 7.
8. The file `FF FF 00 20 00 20 11 00 30 05 30 22` loads with one segment (`$2000`, data `11`) and the defect `ShortData` at offset 7.
9. The file `FF FF 00 20 00 20 11 00 30 FF 2F 22 00 40 00 40 33` loads with one segment (`$2000`, data `11`) and the defect `EndBeforeStart` at offset 7. The segment at `$4000` after the defect is not kept.

## Notes

The emulator reports a defect to the frontend as a warning. The frontend shows the warning to the user.

### Defects

| Defect | Condition |
| --- | --- |
| `ShortHeader` | Fewer than 4 bytes remain for the segment header. |
| `EndBeforeStart` | The end address is less than the start address. |
| `ShortData` | Fewer data bytes remain than the header gives. |
