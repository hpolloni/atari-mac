# REQ-617: Ignored command frames

## Requirement

An emulated SIO device shall send no byte in reply to a command frame that has a different device ID, a checksum error, a framing error or fewer than five bytes.

## Rationale

All devices receive all command frames. A reply to a frame for another device, or to a damaged frame, would interfere with the other devices on the bus.

## Acceptance criteria

All criteria use NTSC timing and an SD image in D1:. Each frame is sent with the command line low, and then the command line goes high. "No byte" means that the drive sends no byte in the 178,977 machine cycles (100 ms) after the command line goes high.

1. The frame `32 53 00 00 85` (device `$32`, valid checksum) gives no byte.
2. The frame `31 53 00 00 85` (checksum error: the checksum of `31 53 00 00` is `$84`) gives no byte.
3. The frame `31 53 00 00 84` with byte 1 at a bit period of 99 cycles (framing error, REQ-615) gives no byte.
4. The four bytes `31 53 00 00` give no byte.
5. After each frame of criteria 1 to 4, the frame `31 53 00 00 84` gets the reply `41 43 00 FF E0 00 E0` (REQ-619).
