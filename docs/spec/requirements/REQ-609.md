# REQ-609: All accesses to the cartridge control region

## Requirement

The emulator shall send each bus access to `$D500-$D5FF` to the cartridge, including CPU dummy reads and ANTIC DMA reads.

## Rationale

The HRM warns that a false read from an indexed addressing mode, or a DMA read, can switch a cartridge bank. Some programs crash on real hardware for this reason. The emulator must give the same result.

## Acceptance criteria

The test images use the bank pattern: each byte of bank `k` holds `k`.

1. With a MaxFlash 1Mbit cartridge at bank 0, the CPU executes `LDA $D5FF,X` (`BD FF D5`) with X = `$08`. The CPU makes a false read of `$D507` and then reads `$D607`. After the instruction, a read of `$A000` gives `$07`.
2. With a MaxFlash 8Mbit cartridge at bank 0, the display list is `4F 40 D5` (mode F with LMS address `$D540`) and then `41` with the address of the display list (JVB). `DMACTL` = `$21` (narrow playfield, display list DMA). ANTIC fetches 32 playfield bytes from `$D540-$D55F` in each frame. After one frame, a read of `$A000` gives `$5F`, the bank of the last fetch.

## Notes

The HRM example: `LDA $D5FF,X` with X = `$08` reads `$D607`, but the false read goes to `$D507`.

Criterion 2 uses the 8Mbit cartridge because each address in `$D500-$D5FF` switches its bank. A fetch from `$D5xx` on the 1Mbit cartridge also passes `$D510-$D51F`, which disables the cartridge.

The system design (REQ-213) gives ANTIC DMA reads with no side effects. Criterion 2 needs a side effect for DMA reads of `$D500-$D5FF`. The media design lists this as an open issue.

CART-TXT type-41 and type-42 say that a write to the control range selects the bank. They do not say that a read selects the bank. The HRM says that the bank registers can switch on a read, also on a false read and a DMA read. This requirement follows the HRM.
