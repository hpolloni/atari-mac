# REQ-080: Run a BASIC program from a text file

## Requirement

When the command line has `--bas <file>`, the emulator shall boot with BASIC, wait for the `Ready` prompt, type each program line of the text file as key presses followed by RETURN, and then type `RUN` and RETURN, except when the command line also has `--no-run`.

## Rationale

A user can keep a BASIC program in a text file, edit it on the Mac, and run it in the emulator without typing it again.

## Acceptance criteria

1. With a file that contains the line `10 PRINT 2+2`, `atari-mac --headless --frames 600 --bas <file>` ends with a screen whose text rows contain `RUN`, then `4`, then `Ready`, in this order.
2. With `--no-run` and the same file, the screen text contains `10 PRINT 2+2` and `Ready`, and no row is `4`.
3. Lines that end with LF and lines that end with CR LF give the same key presses. A line that is empty or has only spaces is not typed. A missing newline at the end of the file has no effect.
4. A file with a character that has no key on the Atari keyboard gives exit code 2 before the machine starts, and a message that names the file, the line number and the character.
5. A file that does not exist or cannot be read gives exit code 2 and a message that names the file.
6. The typing starts only after the `Ready` prompt is on the screen. If `Ready` is not on the screen after 600 frames, the emulator stops with exit code 1 and a message that says that BASIC did not start.
7. In the window, the emulator keeps showing frames while it types, so the user sees the program typed.
8. `--help` lists `--bas <file>` and `--no-run`. `--no-run` without `--bas` gives exit code 2.

## Notes

Project decision of 2026-11-19 (the user): a text listing only, `RUN` automatically, the option names `--bas` and `--no-run`. Tokenized BASIC files (the output of `SAVE`) are not supported. The key presses use the same keyboard path as the harness (REQ-025), so a long program takes some seconds to type.
