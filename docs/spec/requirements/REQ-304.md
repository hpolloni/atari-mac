# REQ-304: Scan line and frame timing

## Requirement

The emulator shall make each scan line 114 machine cycles long, and each frame 262 scan lines long for NTSC and 312 scan lines long for PAL.

## Rationale

All display, DMA and NMI timing depends on these counts. Software identifies an NTSC or a PAL ANTIC with `VCOUNT`.

## Acceptance criteria

1. After power-on, `scanline()` and `cycle()` return 0. After each `tick`, `cycle()` increases by 1. After the tick of cycle 113, `cycle()` returns 0 and `scanline()` increases by 1. After the tick of cycle 113 of scan line 261 (NTSC) or 311 (PAL), `scanline()` returns 0.
2. For 10 frames, `out.frame_done` is set once every 29868 ticks (NTSC, 262 × 114) or once every 35568 ticks (PAL, 312 × 114). No frame has a different length (no interlace).
3. With `NMIEN` = `$40` and `DMACTL` = `$00`, the cycles where `out.nmi` is set are exactly 29868 cycles apart (NTSC) or 35568 cycles apart (PAL), for 10 frames.

## Notes

The ANTIC type sets the frame timing. In a mixed system, the GTIA type sets only the `PAL` register value. The 65XE has matched chips, so this project does not support mixed systems.
