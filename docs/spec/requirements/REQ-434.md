# REQ-434: Timing of mid-line register writes

## Requirement

For a CPU write on machine cycle c, the emulator shall apply the new value from HPOS `2c - 2 + d`, with d = 1 for color registers, 2 for `PRIOR` bits 0-5, 3 for `GRAFP0-3` and `GRAFM`, 4 for `PRIOR` bits 6-7, and 5 for `HPOSPn`, `HPOSMn`, `SIZEPn` and `SIZEM`.

## Rationale

Display list interrupts and kernels change colors and sprites in the middle of a scanline. The position of the change must agree with the hardware.

## Acceptance criteria

In all criteria, the write is a CPU write on machine cycle 65, except where the criterion states other values, and `COLBK` = `$02`.

1. A write of `$46` to `COLPM0`, with player 0 at HPOS `$78-$97` (`HPOSP0` = `$78`, `GRAFP0` = `$FF`, `SIZEP0` = `$03`) and the old `COLPM0` = `$16`: HPOS `$80` (column 192) shows `$16` and HPOS `$81` (column 194) shows `$46`.
2. A write of `$04` to `PRIOR` (old value `$01`), with player 0 of criterion 1 on `PF0`: HPOS `$81` shows `COLPM0` and HPOS `$82` shows `COLPF0`.
3. A write of `$00` to `GRAFP0` (old value `$80`), with `HPOSP0` = `$82`: HPOS `$82` shows `COLPM0`. With `HPOSP0` = `$83` instead, HPOS `$83` shows `$02`.
4. A write of `$40` to `PRIOR` (old value `$00`) on a low resolution line, with `COLBK` = `$90`, `COLPF2` = `$38` and code `%110` at each HPOS from `$78`: HPOS `$83` shows `$38` and HPOS `$84` shows `$9A`.
5. With `GRAFP0` = `$FF` and single width: old `HPOSP0` = `$86` and a write of `$C0` give no player at HPOS `$86-$8D` and a player at HPOS `$C0-$C7`. Old `HPOSP0` = `$84` and a write of `$C0` give a player at HPOS `$84-$8B` and at HPOS `$C0-$C7`. Old `HPOSP0` = `$40` and a write of `$85` give a player at HPOS `$85-$8C`. Old `HPOSP0` = `$40` and a write of `$84` give no player at HPOS `$84-$DD`.
6. A write of `$01` to `SIZEP0` (old value `$00`), with `GRAFP0` = `$FF` and `HPOSP0` = `$80`: the player shows at HPOS `$80-$8A`.
7. A write of `$46` to `COLBK` on machine cycle 30 (old value `$02`): HPOS `$3A` shows `$02` and HPOS `$3B` shows `$46`.

## Notes

The HRM gives the delays for a write on cycle 65 only. There are two color clocks for each machine cycle (HRM 1.4, HRM 2.2), so the project uses `2c - 2` as the general base (project decision). The HRM gives a range of 3-5 color clocks for `PRIOR` bits 6-7 and 2-3 for bit 4. The emulator uses 4 and 2. The transition artifacts of HRM 6.10 (GTIA mode changes) are not modeled.
