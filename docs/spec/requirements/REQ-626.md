# REQ-626: ATR image errors

## Requirement

The emulator shall reject an ATR image that has a short header, a bad signature, a sector size other than 128 or 256, a data size that is not a whole number of sectors, fewer data bytes than the header gives, zero sectors or more than 65535 sectors, and shall report which of these errors occurred.

## Rationale

A bad image must not crash the emulator (REQ-016). Logical sector numbers are 16-bit values, so a disk cannot have more than 65535 sectors.

## Acceptance criteria

The test files start from the valid SD file of REQ-625 criterion 1 (header `96 02 80 16 80 00 00`, 92,160 data bytes). Each criterion changes one thing.

1. The first 15 bytes of the file give the error `AtrHeader`.
2. The file with bytes 0-1 changed to `96 03` gives the error `AtrSignature(0x0396)`.
3. The file with bytes 4-5 changed to `00 02` (sector size 512) gives the error `AtrSectorSize(512)`.
4. The file with bytes 2-3 changed to `81 16` (5761 units, 92,176 bytes) and 16 more data bytes gives the error `AtrDataSize(92176)`.
5. The file with only 92,000 data bytes gives the error `AtrTruncated { expected: 92160, actual: 92000 }`.
6. The file with bytes 2-3 changed to `00 00` and no data bytes gives the error `AtrSectorCount(0)`.
7. The file with bytes 2-3 changed to `00 00`, byte 6 changed to `08` (`$080000` units, 8,388,608 bytes) and 8,388,608 data bytes gives the error `AtrSectorCount(65536)`.
8. The file with bytes 4-5 changed to `00 01` (sector size 256) and bytes 2-3 changed to `19 00` (25 units, 400 bytes), with 400 data bytes, gives the error `AtrDataSize(400)`. (400 is not `384 + k * 256` and not `k * 256`.)
9. A file of 15 bytes that starts with `96 03` gives `AtrHeader`. The emulator checks the errors in this order and reports the first error: `AtrHeader`, `AtrSignature`, `AtrSectorSize`, `AtrTruncated`, `AtrDataSize`, `AtrSectorCount`.

## Notes

Sector size 512 is out of scope. The HRM states that some hard disks use it.
