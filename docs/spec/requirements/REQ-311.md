# REQ-311: Virtual playfield DMA cycles

## Requirement

The emulator shall not halt the CPU for a playfield fetch on cycle 106 or later, and shall still increment the memory scan counter and the line buffer address for that fetch.

## Rationale

Wide playfields and horizontally scrolled playfields have fetches after cycle 105. A hardware stop blocks these fetches. This changes the CPU timing at the end of the scan line and the memory scan counter for the next mode line.

## Acceptance criteria

1. With `DMACTL` = `$23`, on the first scan line of a mode E line, the `Bitmap` fetch on cycle 104 sets `out.halt`, and the fetch on cycle 106 does not set `out.halt`.
2. After that mode E line with LMS `$3000`, the first fetch of the next mode line without LMS reads `$3030` (48 fetches).
3. The fetch on cycle 106 loads line buffer byte 47 (the 48th byte) with the data bus value of cycle 106 (REQ-347).
4. With `DMACTL` = `$23`, on the first scan line of a mode 6 line, the `CharacterData` fetch on cycle 105 sets `out.halt`.

## Notes

HRM 4.14 says that fetches on cycle 106 or later are suppressed, and HRM 4.9 says that playfield DMA can occupy cycle 105. HRM 4.12 says that abnormal playfield DMA cycles are suppressed during cycles 105-111 and 0. This requirement uses HRM 4.14 and 4.9 for normal playfield DMA. REQ-347 gives the data that ANTIC loads on a virtual cycle.
