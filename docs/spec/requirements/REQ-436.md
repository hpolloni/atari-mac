# REQ-436: Trigger latch

## Requirement

When `GRACTL` bit 2 = 1, the emulator shall keep each `TRIGn` at 0 after its input becomes active, until `GRACTL` bit 2 is set to 0.

## Rationale

Programs set the latch to catch a short button press between two reads. Light pen programs also use it.

## Acceptance criteria

1. With `GRACTL` = `$04`, a press and release of the port 1 button makes `TRIG0` read `$00` after the release.
2. After criterion 1, a write of `$00` to `GRACTL` makes `TRIG0` read `$01`, with the button released.
3. With `GRACTL` = `$00`, `TRIG0` reads `$01` at the first read after the release.
4. With `GRACTL` = `$04`, for each trigger input n = 0, 1 and 3, an active input followed by an inactive input makes `TRIGn` read `$00` after the input becomes inactive.
5. With trigger input 0 active, a write of `$04` to `GRACTL` followed by a release of the input makes `TRIG0` read `$00`.

## Notes

The HRM does not state how the latch is cleared. GTIA-SPEC 7.0, TRN HW-III.D/GRACTL and TRN HW-III.I/TRIG0-TRIG3 state that a 0 in `GRACTL` bit 2 clears all trigger latches. Thus the release of the latch is not a project decision.
