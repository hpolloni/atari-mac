# REQ-427: Multicolor players

| Field | Value |
| --- | --- |
| Status | Draft |
| Priority | Should |
| Area | GTIA, color palette, joystick and paddle inputs |
| Source | HRM 6.7 Priority control (Multiple color player enable) |
| Verification | Test |
| Depends on | REQ-424 |

## Requirement

When `PRIOR` bit 5 = 1, the emulator shall show the bitwise OR of the two color registers where the objects of a pair `P0`+`P1`, `P2`+`P3`, `M0`+`M1` or `M2`+`M3` overlap.

## Rationale

Programs use overlapped players to get a third color in a sprite.

## Acceptance criteria

In all criteria, `COLPM0` = `$42`, `COLPM1` = `$94`, `COLPM2` = `$06` and `COLPM3` = `$C0`.

1. With `PRIOR` = `$21`, players 0 and 1 at the same color clock show `$D6`.
2. With `PRIOR` = `$01`, players 0 and 1 at the same color clock show `$42`.
3. With `PRIOR` = `$21`, players 2 and 3 at the same color clock show `$C6`.
4. With `PRIOR` = `$21`, missiles 0 and 1 at the same color clock show `$D6`, and missiles 2 and 3 at the same color clock show `$C6`.
5. With `PRIOR` = `$21`, players 0 and 2 at the same color clock show `$42`.
6. With `PRIOR` = `$21`, players 0 and 1 at the same color clock set `P0PL` = `$02` and `P1PL` = `$01`.
