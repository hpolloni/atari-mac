# REQ-102: Page crossing on indexed reads

| Field | Value |
| --- | --- |
| Status | Draft |
| Priority | Must |
| Area | CPU (6502C) |
| Source | HRM 3.3 Cycle timing (Crossing page boundaries) |
| Verification | Test |
| Depends on | REQ-101 |

## Requirement

The emulator shall add one cycle to an `abs,X`, `abs,Y` or `(zp),Y` read that crosses a page, and shall do a dummy read in that cycle at the address with the uncorrected high byte.

## Rationale

The 6502 reads speculatively before it adds the carry to the high byte (HRM 3.3). The extra cycle changes timing, and the dummy read can touch a hardware register.

## Acceptance criteria

1. Start: `X` = `$80`. `LDA $20F0,X` takes 5 cycles. Cycle 4 reads `$2070` (dummy read). Cycle 5 reads `$2170` (operand).
2. Start: `Y` = `$80`. `LDA $20F0,Y` takes 5 cycles. Cycle 4 reads `$2070`. Cycle 5 reads `$2170`.
3. Start: `Y` = `$80`, `$0040` = `$F0`, `$0041` = `$20`. `LDA ($40),Y` takes 6 cycles. Cycle 5 reads `$2070`. Cycle 6 reads `$2170`.
4. Start: `X` = `$10`. `LDA $2000,X` takes 4 cycles. Cycle 4 reads `$2010` (operand). There is no dummy read.
5. Start: `Y` = `$10`, `$00FF` = `$00`, `$0000` = `$20`. `LDA ($FF),Y` takes 5 cycles. Cycle 5 reads `$2010`.
6. Start: `X` = `$20`, `Y` = `$20`. `LDA $F0,X` takes 4 cycles, `LDX $F0,Y` takes 4 cycles, and `LDA ($F0,X)` takes 6 cycles.

## Notes

Undocumented `NOP` opcodes with `abs,X` also add the cycle on a page crossing (HRM 3.5 NOP). REQ-111 covers this case.
