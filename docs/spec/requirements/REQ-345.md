# REQ-345: Abnormal playfield DMA

## Requirement

The emulator shall model the playfield DMA clock as a shift ring that is 2, 4 or 8 cycles long, where ANTIC injects one bit at the playfield start and clears one bit position at the playfield stop, so that a stop at a wrong position lets playfield DMA continue into the next scan line.

## Rationale

Some programs change `HSCROL` or `DMACTL` at bad times, or put a mode 8 or 9 line after a scrolled line. Hardware then shows garbled lines. Accurate emulation must show the same result.

## Acceptance criteria

1. A `$18` line (scrolled mode 8) with `DMACTL` = `$22` starts with `HSCROL` = `$00`. A write of `$02` to `HSCROL` on cycle 50 of its first scan line. On the following scan lines, the DMA clock in the debug state, in the bit order of HRM 4.12, cycles through `%01000010`, `%01001000`, `%01100000` and `%11000000`, and repeats every four scan lines. The abnormal bits are not cleared (HRM 4.12, Abnormal DMA patterns across scan lines).
2. On each cycle where two DMA requests occur together, the `DmaMemory` log has one read on that cycle, at the bitwise AND of the two request addresses, and both requests get the byte of that read. A refresh never occurs on such a cycle.
3. After the abnormal state of criterion 1, the DMA clock in the debug state is 0 after the tick of cycle 1 of the first scan line of a `$00` or `$01` instruction, and after the tick of cycle 0 of scan line 248.
4. With `DMACTL` = `$22`, a `$5E $00 $30` line (scrolled mode E, LMS `$3000`) with `HSCROL` = 10 is followed by a `$08` line without LMS. After the mode 8 line, the memory scan counter is not `$303A`. With `HSCROL` = 8, it is `$303A`. A `$5A $00 $30` line with `HSCROL` = 14 followed by a `$08` line gives a memory scan counter that is not `$3022`. With `HSCROL` = 12, it is `$3022`.
5. With `DMACTL` = `$21` and `HSCROL` = 10, a `$5E $00 $30` line followed by a `$08` line gives the memory scan counter `$3030` after the mode 8 line (no error).
6. In an abnormal state with more than 48 line buffer accesses on one scan line, accesses 49-63 do not change the line buffer, reads in these accesses give `$FF`, and access 64 uses line buffer byte 0 again.

## Notes

The HRM describes the clocks in detail but not every gate. The design gives the model. Exact results for all cases are an open issue.

Criterion 1 uses the bit order of the HRM 4.12 table. The design document must give the mapping from this bit order to its model of the DMA clock.

Criteria 4 and 5 check only that the memory scan counter is wrong or correct. The HRM does not give the wrong value.

Criterion 1 uses the `HSCROL` = `$02` example of HRM 4.12 (decision of the user, 2026-11-19). The table of the `$04` example in the same section cannot be produced by an 8-stage DMA clock, so it is recorded as a suspected HRM error in OI-024.
