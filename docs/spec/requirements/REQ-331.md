# REQ-331: NMI status and reset

## Requirement

The emulator shall set `NMIST` bit 7 for each DLI and bit 6 for each VBI, whether or not `NMIEN` enables them, and shall clear bits 7-5 on any write to `NMIRES`.

## Rationale

All ANTIC NMIs use one CPU vector. The OS NMI handler reads `NMIST` to find the source.

## Acceptance criteria

1. On every cycle of a frame with DLIs and a VBI, a read of `NMIST` gives bits 4-0 = `%11111`.
2. After the VBI, a DLI occurs on scan line 40. A read of `NMIST` on cycle 7 of scan line 40 gives bit 7 = 1 and bit 6 = 0.
3. After that DLI, a read of `NMIST` on cycle 7 of scan line 248 gives bit 7 = 0 and bit 6 = 1.
4. With `NMIEN` = `$00`, the reads of criteria 2 and 3 give the same values, and `out.nmi` is never set.
5. After a write of `$00` or of `$FF` to `$D40F`, a read of `$D40F` returns `$1F`.
6. After a DLI on scan line 40, with no write to `NMIRES`, `NMIST` bit 7 reads 1 on every cycle from scan line 40, cycle 7 to scan line 248, cycle 6.
7. After power-on (`NMIST` = `$7F`) and a write to `NMIRES`, `NMIST` bit 5 reads 0 on every cycle of the next 2 frames, also after a reset in the first of these frames.

## Notes

Zaxxon II reads `NMIST` more than one scan line after its DLI starts, and needs the DLI bit to stay set (HRM 4.16).

The 65XE has no reset NMI. The RESET key resets the system instead (HRM 4.8). The power-on value `$7F` has bit 5 set (REQ-303).
