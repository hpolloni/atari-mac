# REQ-606: CAR image errors

## Requirement

The emulator shall reject a CAR image that has a short header, a bad signature, an unsupported type, a data size that does not agree with the type, or a wrong checksum, and shall report which of these errors occurred.

## Rationale

A bad file must not crash the emulator or start a program from bad data (REQ-016).

## Acceptance criteria

The test files start from the valid type 1 file of REQ-605 criterion 1 (16-byte header, 8192 data bytes in the offset pattern, checksum `$0001F000`). Each criterion changes one thing.

1. The first 15 bytes of the file give the error `CarHeader`.
2. The file with bytes 0-3 changed to `43 41 52 58` (`CARX`) gives the error `CarSignature`.
3. The file with bytes 4-7 changed to `00 00 00 63` (type 99) gives the error `CarType(99)`.
4. The file without its last byte (8191 data bytes) gives the error `CarSize { car_type: 1, expected: 8192, actual: 8191 }`.
5. The file with bytes 8-11 changed to `00 01 F0 01` gives the error `CarChecksum { stored: 0x0001F001, computed: 0x0001F000 }`.
6. A file of 15 bytes that starts with `CARX` gives `CarHeader`. The emulator checks the errors in the order of criteria 1 to 5 and reports the first error.

## Notes

To reject a checksum mismatch is a project decision. A later change can make it a warning.
