# REQ-120: Interrupt after SEI and PLP

| Field | Value |
| --- | --- |
| Status | Draft |
| Priority | Should |
| Area | CPU (6502C) |
| Source | HRM 3.4 Interrupts (Setting the I flag with an interrupt pending) |
| Verification | Test |
| Depends on | REQ-119 |

## Requirement

The emulator shall service a pending IRQ after a `CLI`+`SEI` or `CLI`+`PLP` pair that sets `I` again, with `I` = 1 in the pushed `P`.

## Rationale

`CLI` followed by `SEI` is a common way to service pending IRQs at a known time (HRM 3.4). The IRQ handler then sees `I` = 1 in the pushed flags.

## Acceptance criteria

1. Start: `I` = 1, the IRQ line asserted, `CLI` at `$0200`, `SEI` at `$0201`. The IRQ sequence starts directly after the `SEI`. It pushes the return address `$0202` and `P` with bit 2 (`I`) = 1.
2. Start: `I` = 1, the IRQ line asserted, `S` = `$FE`, `$01FF` = `$24`, `CLI` at `$0200`, `PLP` at `$0201`. The IRQ sequence starts directly after the `PLP`. It pushes the return address `$0202` and `P` with `I` = 1.
3. Start: the IRQ line asserted. One of these pairs runs, and then 10 `NOP` instructions: `CLI`+`RTI`, `PLP`+`SEI`, `PLP`+`RTI` and `PLP`+`PLP`. In each pair, the first instruction clears `I` and the second instruction sets `I`. No IRQ sequence starts during the pair or the 10 `NOP` instructions.
4. Start: `I` = 1, the IRQ line asserted. An `RTI` that pulls `I` = 0 is followed by `SEI`, by an `RTI` that pulls `I` = 1, or by a `PLP` that pulls `I` = 1. The IRQ sequence starts directly after the first `RTI` (REQ-119), and the second instruction does not execute before it. The pushed `P` has `I` = 0.

## Notes

HRM 3.4 says that the effect does not occur for CLI+RTI, PLP+[SEI/RTI/PLP] and RTI+[SEI/RTI/PLP], and that no IRQ is dispatched for these pairs. For the RTI pairs, this text does not agree with the statement that an IRQ can be serviced directly after an RTI that clears I. Criterion 4 is the project reading: the RTI pairs do not show the effect, and REQ-119 still applies. The HRM text does not explain why PLP+SEI differs from CLI+SEI. Criterion 3 uses the HRM statement.

Open question: HRM 3.4 also says that an IRQ occurs after the instruction that follows a `PLP` that clears `I` (REQ-119). For `PLP`+`SEI`, that rule gives an IRQ after the `SEI`, but criterion 3 gives no IRQ. The CPU design (cpu.md, "Open issues", item 2) gives an IRQ. A decision is necessary before the test `pairs_without_irq_dispatch` is written.
