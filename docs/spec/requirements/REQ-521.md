# REQ-521: Keyboard overrun

| Field | Value |
| --- | --- |
| Status | Draft |
| Priority | Should |
| Area | POKEY: audio, timers, keyboard, interrupts, serial port |
| Source | HRM 5.8 Keyboard scan (Keyboard overruns); HRM 14.4 POKEY registers (SKRES, SKSTAT) |
| Verification | Test |
| Depends on | REQ-518 |

## Requirement

The emulator shall set `SKSTAT` bit 6 to 0 when a key press registers while `IRQST` bit 6 is 0, and shall set `SKSTAT` bits 5, 6 and 7 to 1 on each write to `SKRES`.

## Rationale

Programs can detect lost key presses through the overrun bit.

## Acceptance criteria

In all criteria, `SKCTL` = `$03`. Each key press holds the key down for 200 x 114 cycles and then up for 200 x 114 cycles.

1. With `IRQEN` = `$40`, the test presses A. After the press registers, `SKSTAT` bit 6 reads 1. Then the test presses S with no write to `IRQEN`. After the S press registers, `SKSTAT` bit 6 reads 0 and `KBCODE` reads `$3E`.
2. After criterion 1, a write to `SKRES` on cycle X makes `SKSTAT` bit 6 read 1 from cycle X+1. REQ-529 criterion 5 checks bits 5 and 7.
3. Two instances run criterion 1. One instance also reads `KBCODE` on each cycle. The reads of `IRQST` and `SKSTAT` (with `peek`) of the two instances are the same on each cycle.
4. With `IRQEN` = `$C0` and `IRQST` bit 6 = 0 after a press of A, presses of Shift, Control and BREAK keep `SKSTAT` bit 6 at 1.
