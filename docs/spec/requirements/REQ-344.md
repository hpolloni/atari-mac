# REQ-344: Playfield DMA changes in the middle of a scan line

## Requirement

The emulator shall apply a change of `DMACTL` bits 1-0 or `HSCROL` in the middle of a scan line to the playfield start only if the write is before the start deadline, and to the playfield stop only if the write is before the stop deadline, with the deadlines in the table below.

| Fetch width | Start deadline (last cycle) | Stop deadline (last cycle) |
| --- | --- | --- |
| Narrow | 24 + (`HSCROL` >> 1) | 88 + (`HSCROL` >> 1) |
| Normal | 16 + (`HSCROL` >> 1) | 96 + (`HSCROL` >> 1) |
| Wide | 8 + (`HSCROL` >> 1) | 104 + (`HSCROL` >> 1) |

## Rationale

DLI handlers often write `DMACTL` too late. Pacem in Terris misses the deadline, and the hardware result is a blank scan line and a bitmap one scan line lower (HRM 4.16).

## Acceptance criteria

1. A mode E line with all bytes `$FF` starts with `DMACTL` = `$21`. A write of `$22` on cycle 50 makes the playfield code `%110` on positions `$40-$CF` (144 color clocks) and `%000` on positions `$22-$3F` and `$D0-$DD`. The memory scan counter increases by 36.
2. A mode E line starts with `DMACTL` = `$22`. A write of `$21` on cycle 17 (after the normal start deadline, before the narrow start deadline) does not move the start: the playfield starts at position `$30`. The stop moves: the playfield stops after position `$BF`.
3. A mode E line starts with `DMACTL` = `$21`. A write of `$22` on cycle 20 (after the normal start deadline, before the narrow start deadline) gives no playfield on that scan line: positions `$22-$DD` have code `%000`, no `Bitmap` fetch occurs, and the memory scan counter does not change.
4. A mode E line starts with `DMACTL` = `$22`. A write of `$21` on cycle 95 (after the narrow stop deadline) extends the playfield to the wide stop: `Bitmap` fetches also occur on cycles 100, 102 and 104, a virtual fetch occurs on cycle 106, and the memory scan counter increases by 44.
5. A mode E line starts with `DMACTL` = `$22`. A write of `$20` on cycle 50: no `Bitmap` fetch occurs after cycle 51, and positions `$70-$CF` have code `%000`. The memory scan counter increases by 40. Line buffer bytes 16-39 hold the data bus values of cycles 52, 54, ..., 98.
6. A write of `$20` to `DMACTL` on cycle 10 of the first scan line of a normal mode E line: the memory scan counter and the line buffer do not change.
7. A `$1F` line (scrolled mode F) with `DMACTL` = `$22` and different screen bytes starts with `HSCROL` = 0. A write of `$01` to `HSCROL` on cycle 60 gives the same `out.dma` as with no write. For each position x from `$80` to `$CF`, the code at x is equal to the code at x - 1 of the same line with no write.
8. Removed (OI-014): the codes in IR modes 2 and 3 while playfield DMA is off need a comparison with Altirra. The number is kept, so that the numbers of the other criteria do not change.

## Notes

The "previous case" of HRM 4.11 (Mid scan line changes) is also missing from the PDF. Decision (OI-014): after the playfield start, a fetch cycle with DMA off loads the data bus value and advances the memory scan counter (criterion 5). If DMA is off at the playfield start, the line buffer does not change (HRM 4.4).

Criteria 2 and 4 follow from the deadline rules of HRM 4.11 and the fetch cycles of REQ-309.
