# REQ-518: Keyboard scan and debounce

## Requirement

With `SKCTL` bits 0 and 1 both 1, the emulator shall detect key presses and releases with the four-state scan state machine of HRM 5.8, which checks one of the 64 key codes on each 15 kHz clock pulse.

## Rationale

The OS reads all typed characters through this scan and the keyboard IRQ. The test harness types text through it (REQ-025).

## Acceptance criteria

In all criteria, `SKCTL` = `$03` is written at least 300 x 114 cycles before the first key goes down, `IRQEN` = `$40`, and Shift and Control are up. "A key goes down on cycle K" means that the test calls `set_key(code, true)` before the tick of cycle K.

1. When only the A key (`$3F`) goes down on cycle K, `KBCODE` reads `$3F`, `IRQST` bit 6 reads 0 and `SKSTAT` bit 2 reads 0, all first on the same cycle R.
2. In criterion 1, R - K is from 63 x 114 to 129 x 114 cycles.
3. When the A key goes up on cycle U, after it registered and was down for 200 x 114 cycles, `SKSTAT` bit 2 reads 1 first on a cycle V. V - U is from 63 x 114 to 129 x 114 cycles. `KBCODE` and `IRQST` do not change from cycle U to cycle V+1000.
4. When the A and S keys go down on the same cycle and stay down for 300 x 114 cycles, `IRQST` bit 6 reads 1, `SKSTAT` bit 2 reads 1 and `KBCODE` does not change.
5. When the S key goes down 10 x 114 cycles after the A key registered, and both keys stay down for 300 x 114 cycles, `KBCODE` reads `$3F` and `SKSTAT` bit 2 reads 0. The test clears `IRQST` bit 6 (`IRQEN` = `$00`, then `$40`) after the A key registered. `IRQST` bit 6 then reads 1 for the 300 x 114 cycles.
6. The A key is down for 200 x 114 cycles, up for 200 x 114 cycles and down again for 200 x 114 cycles. The test clears `IRQST` bit 6 after the first press registered. Each press makes `IRQST` bit 6 read 0 within 129 x 114 cycles after the key goes down, and `KBCODE` reads `$3F` after each press.

## Notes

The states of HRM 5.8 are: 0 (key up), 1 (debounce key down), 3 (confirmed key down) and 2 (debounce key up). A full scan takes 64 pulses of the 15 kHz clock (about 4 ms). A key press needs two scans to register, and a release needs two scans. So the maximum typing rate is about 60 characters per second.

There is no auto-repeat in POKEY. The OS does the key repeat in software.

The HRM does not state the transition of state 2 when the key is down again on a compare match. See the open issues in `docs/design/pokey.md`.

POKEY-SPEC 3 gives the same scan state machine as a flow chart. The binary counter counts once per line, and when a second key closes before the compare match, the scan ignores both keys.
