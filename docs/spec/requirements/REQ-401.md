# REQ-401: Read and write register meanings

## Requirement

The emulator shall return the read register of HRM Table 13 for a CPU read and change the write register of Table 13 for a CPU write at the same address.

## Rationale

Most GTIA addresses have one register for reads and a different register for writes. For example, `$D000` is `HPOSP0` for writes and `M0PF` for reads. Software that reads a write-only register gets the read register.

## Acceptance criteria

1. Read map. Each state below gives the stated read values. All collision registers that the criterion does not name read `$00`.
   - For n = 0-3, missile n alone on a `PF0` pixel: `$D000 + n` (`MnPF`) reads `$01`.
   - For n = 0-3, player n alone on a `PF0` pixel: `$D004 + n` (`PnPF`) reads `$01`.
   - For n = 0-3 and m = (n + 1) mod 4, missile n and player m alone at one background pixel: `$D008 + n` (`MnPL`) reads `1 << m`, and `$D004 + m` reads `$00`.
   - For n = 0-3 and m = (n + 1) mod 4, players n and m alone at one background pixel: `$D00C + n` (`PnPL`) reads `1 << m`, and `$D00C + m` reads `1 << n`.
   - For n = 0, 1 and 3, with trigger input n active: `$D010 + n` (`TRIGn`) reads `$00`. With the input inactive, it reads `$01`.
   - `$D014` (`PAL`) gives the values of REQ-403. `$D01F` (`CONSOL`) gives the values of REQ-437.
2. Write map. From the power-on state, each write below gives the stated result on the next scanline. In this criterion, `COLPMn` = `$0E` before the write, except where the criterion writes `COLPMn`.
   - `$D000 + n` (`HPOSPn`, n = 0-3): with `GRAFPn` = `$80`, a write of `$80` makes HPOS `$80` show `$0E`.
   - `$D004 + n` (`HPOSMn`, n = 0-3): with `GRAFM` = `$FF`, a write of `$80` makes HPOS `$80-$81` show `$0E`.
   - `$D008 + n` (`SIZEPn`, n = 0-3): with `HPOSPn` = `$80` and `GRAFPn` = `$80`, a write of `$01` makes HPOS `$80-$81` show `$0E`.
   - `$D00C` (`SIZEM`): with `HPOSM0` = `$80` and `GRAFM` = `$02`, a write of `$01` makes HPOS `$80-$81` show `$0E`.
   - `$D00D + n` (`GRAFPn`, n = 0-3): with `HPOSPn` = `$80`, a write of `$80` makes HPOS `$80` show `$0E`.
   - `$D011` (`GRAFM`): with `HPOSM0` = `$80`, a write of `$02` makes HPOS `$80` show `$0E`.
   - `$D012-$D01A`: a write of `$46` makes player 0, player 1, player 2, player 3, `PF0`, `PF1`, `PF2`, `PF3` or background pixels, in this order of address, show `$46`.
   - `$D01B` (`PRIOR`): with `COLPM0` = `$40`, `COLPF0` = `$0A` and player 0 on a `PF0` pixel, the pixel shows `$4A` before the write and `$0A` after a write of `$04`.
   - `$D01C` (`VDELAY`), `$D01D` (`GRACTL`), `$D01E` (`HITCLR`) and `$D01F` (`CONSOL`): the criteria of REQ-415, REQ-414, REQ-423 and REQ-437 pass with writes to these addresses.
3. After a write of `$80` to `$D000` and with no collisions, a read of `$D000` returns `$00`.
4. With all 60 collision bits set, `M0PF-M3PF` and `P0PF-P3PF` read `$0F`, `M0PL-M3PL` read `$0F` and each `PnPL` reads `$0F AND NOT (1 << n)`. `TRIG0-TRIG3` read only `$00` or `$01`. `CONSOL` reads a value in `$00-$0F` for all key states and all written values.
5. With the NTSC configuration and with the PAL configuration, a read of each address `$D015-$D01E` returns `$0F`.
6. For each address `$D000-$D01F`, two reads with no write, no input change and no display cycle between them return the same value.

## Notes

The HRM states that GTIA drives all data bits in its range, so no bit floats on a read. The value `$0F` for `$D015-$D01E` comes from the read column of Table 13. The HRM also says that the `PAL` value on an NTSC GTIA is the value of an unassigned address. The HRM does not say if a PAL GTIA returns `$0F` or `$01` at `$D015-$D01E`. The project uses `$0F` for both standards, as Table 13 shows.
