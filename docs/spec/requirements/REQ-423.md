# REQ-423: HITCLR

| Field | Value |
| --- | --- |
| Status | Draft |
| Priority | Must |
| Area | GTIA, color palette, joystick and paddle inputs |
| Source | HRM 6.6 Collision detection (Resetting collision latches); HRM 14.3 GTIA registers (HITCLR) |
| Verification | Test |
| Depends on | REQ-420, REQ-421 |

## Requirement

The emulator shall clear all 60 collision bits when the CPU writes any value to `HITCLR` (`$D01E`), and shall keep each collision bit set until such a write.

## Rationale

The collision bits are latches. Programs clear them once each frame.

## Acceptance criteria

1. After a collision and a write of `$00` to `HITCLR`, all registers `$D000-$D00F` read `$00`. A write of `$FF` gives the same result.
2. With no `HITCLR` write, a collision bit that is set on scanline 50 still reads 1 on scanline 200 of the same frame and in the next two frames, also with no further collision.
3. A collision after a `HITCLR` write sets the bit again.

## Notes

Source: project decision for the timing. The HRM does not give the delay of `HITCLR`. The emulator clears the bits at the color clock of the write (`2c - 2`, see REQ-434).
