# REQ-625: ATR disk images

## Requirement

The emulator shall load an ATR disk image with 128-byte or 256-byte sectors, and shall give the drive one logical sector, numbered from 1, for each sector in the image.

## Rationale

ATR is the most common disk image format. The common formats are single density (SD, 720 sectors of 128 bytes, 90 KB), enhanced density (ED, 1040 sectors of 128 bytes, 130 KB) and double density (DD, 720 sectors of 256 bytes, 180 KB).

## Acceptance criteria

Each test file has a 16-byte header that starts with the given bytes, and header bytes 7-15 are `$00`. The data bytes follow the header. Data byte `i` holds `i & $FF`.

1. Header `96 02 80 16 80 00 00` and 92,160 data bytes: the image loads with no error, with 720 sectors of 128 bytes (SD).
2. Header `96 02 80 20 80 00 00` and 133,120 data bytes: the image loads with no error, with 1040 sectors of 128 bytes (ED).
3. Header `96 02 E8 2C 00 01 00` and 183,936 data bytes: the image loads with no error, with 720 sectors (DD). Sectors 1-3 have 128 bytes. Sectors 4-720 have 256 bytes.
4. Sector 1 of the SD image is equal to file bytes 16 to 143. Sector 720 of the SD image is equal to file bytes 92,048 to 92,175.
5. Sector 3 of the DD image is equal to file bytes 272 to 399. Sector 4 of the DD image is equal to file bytes 400 to 655. Sector 720 of the DD image is equal to file bytes 183,696 to 183,951.
6. The SD file of criterion 1 with 100 more bytes after the data loads with no error, with 720 sectors of 128 bytes. Sector 720 is equal to file bytes 92,048 to 92,175.
7. Header `96 02 00 00 80 00 02` (data size `$020000` units, 2,097,152 bytes) and 2,097,152 data bytes: the image loads with no error, with 16384 sectors of 128 bytes.

## Notes

The HRM does not describe the ATR format.

To verify: some tools store flags in bytes 7-15 (for example a write-protect flag). This emulator ignores them.

To verify: some old DD images store sectors 1-3 as full 256-byte sectors (data size `N * 256`). The design document gives a rule for these images.

Other sector counts (for example 16384 sectors of 128 bytes) are permitted. The HRM states that a disk can have any size up to 65535 sectors.

### Format

| Offset | Size | Contents |
| --- | --- | --- |
| 0 | 2 | Signature `$96 $02` (the word `$0296`, low byte first) |
| 2 | 2 | Data size in 16-byte units, bits 0-15, low byte first |
| 4 | 2 | Sector size in bytes (128 or 256), low byte first |
| 6 | 1 | Data size in 16-byte units, bits 16-23 |
| 7 | 9 | Not used by this emulator. Kept on export. |
| 16 | n | Sector data, sector 1 first |

In an image with 256-byte sectors, sectors 1, 2 and 3 have 128 bytes each. Thus the data size of a DD image with N sectors is `3 * 128 + (N - 3) * 256`.
