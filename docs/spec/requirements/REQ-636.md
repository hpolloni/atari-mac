# REQ-636: Boot from D1:

## Requirement

With a bootable disk image in D1: and no cartridge, the emulator shall boot the image at a cold reset with AltirraOS.

## Rationale

A disk boot is the start of all DOS and of most disk software. The OS reads sector 1, and the header in sector 1 gives the number of boot sectors to read.

## Acceptance criteria

The test images have a boot header in sector 1 for a load address of `$0700` (the design document gives the header bytes). The OS loads the boot sectors to `$0700` and calls the code at `$0706`. The machine has AltirraOS, the BASIC ROM and no cartridge.

1. SD test image: the boot header gives 1 boot sector, and the code at offset 6 of sector 1 is `A9 A5 8D 00 06 4C 0B 07` (`LDA #$A5`, `STA $0600`, `JMP $070B`). The other sectors hold `$00`. After a cold reset, `$0600` holds `$A5` within 300 frames (NTSC).
2. Criterion 1 passes for PAL, within 250 frames.
3. Criteria 1 and 2 pass with the SIOV shortcut off and with the SIOV shortcut on (REQ-623).
4. DD test image (720 sectors of 256 bytes): the boot header gives 3 boot sectors, and the code at offset 6 of sector 1 is `4C 00 08` (`JMP $0800`). Sector 3 starts with `A9 A5 8D 00 06 4C 05 08` (`LDA #$A5`, `STA $0600`, `JMP $0805`). After a cold reset, `$0600` holds `$A5` within 300 frames (NTSC).

## Notes

TRN OS-10/Diskette-Booted-Software gives the boot header: a flags byte, the number of boot sectors, the load address and the init address. The OS calls the load address + 6 with `JSR`.

TRN OS-10/Diskette-Booted-Software says that the number of boot sectors is 1 to 255, and that 0 gives 256 sectors. The HRM says that the boot loader is 1-255 sectors long. This requirement follows the HRM. The test images do not use the value 0.
