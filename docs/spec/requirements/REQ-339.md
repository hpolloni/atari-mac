# REQ-339: Player/missile DMA

| Field | Value |
| --- | --- |
| Status | Draft |
| Priority | Must |
| Area | ANTIC |
| Source | HRM 4.13 Player/missile DMA (P/M DMA timing, P/M DMA enable timing); HRM 14.6 ANTIC registers (DMACTL) |
| Verification | Test |
| Depends on | REQ-305, REQ-340 |

## Requirement

The emulator shall fetch the missile byte on cycle 0 and the player 0-3 bytes on cycles 2-5 of each scan line from 8 to 247, when `DMACTL` bit 2 (missiles) or bit 3 (players) enables them, and shall send the bytes to GTIA.

## Rationale

Most games use player/missile graphics. GTIA receives the data from ANTIC DMA.

## Acceptance criteria

1. With `DMACTL` = `$04`, on scan lines 8-247, `out.dma` is `Missile` on cycle 0 and never `Player`.
2. With `DMACTL` = `$08`, on scan lines 8-247, `out.dma` is `Missile` on cycle 0, and `Player` on cycles 2-5.
3. With `DMACTL` = `$0C`, `out.dma` is `Player(0)`, `Player(1)`, `Player(2)` and `Player(3)` on cycles 2, 3, 4 and 5.
4. With `DMACTL` = `$0C`, `out.dma` is never `Missile` or `Player` on scan lines 0-7 and 248 to the end of the frame.
5. With `DMACTL` = `$0C`, a write of `$00` on cycle 112 of scan line 100 prevents the `Missile` fetch on cycle 0 of scan line 101. The same write on cycle 113 does not prevent it.
6. With `DMACTL` = `$00`, a write of `$04` on cycle 112 of scan line 100 makes a `Missile` fetch occur on cycle 0 of scan line 101. The same write on cycle 113 does not.
7. On each P/M DMA cycle, `out.halt` is set and `out.dma_data` is the byte at the fetch address of REQ-340.

## Notes

GTIA also needs `GRACTL` set to store the data (HRM 14.6, DMACTL). GTIA finds the P/M data by the position of the halted cycles in horizontal blank (HRM 6.5). The design document gives the signals that ANTIC sends.
