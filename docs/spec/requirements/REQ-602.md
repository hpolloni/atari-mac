# REQ-602: Writes to cartridge ROM

| Field | Value |
| --- | --- |
| Status | Draft |
| Priority | Must |
| Area | Media |
| Source | HRM 2.6 Bank switching (Writes to ROM) |
| Verification | Test |
| Depends on | REQ-600 |

## Requirement

The emulator shall ignore a CPU write to an address where cartridge ROM is visible, and the write shall not change the RAM at that address.

## Rationale

The MMU selects the device from the address only. A write to ROM does not "write through" to the RAM below it. Some programs write to the cartridge area by accident.

## Acceptance criteria

The 8 KB cartridge image has 8192 bytes of `$CC`. The 16 KB cartridge image has 16384 bytes of `$CC`. The MaxFlash 1Mbit image has 131072 bytes of `$DD`. All writes are CPU writes.

1. The RAM at `$A000` holds `$77`. With the 8 KB cartridge, a write of `$00` to `$A000` and then a read of `$A000` gives `$CC`, and the RAM at `$A000` still holds `$77`.
2. The RAM at `$8000` holds `$77`. With the 16 KB cartridge, a write of `$00` to `$8000` and then a read of `$8000` gives `$CC`, and the RAM at `$8000` still holds `$77`.
3. With the MaxFlash 1Mbit cartridge (REQ-608) and `PORTB` bit 1 = 1: access `$D510` (disable), write `$33` to `$A000`, access `$D500` (bank 0, enabled), write `$44` to `$A000`, and access `$D510` again. A read of `$A000` then gives `$33`.

## Notes

Acceptance criterion 3 applies only when REQ-608 is implemented.

REQ-206 (system area) states the same rule for all ROM areas.
