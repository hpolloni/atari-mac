# REQ-056: README status is current

## Requirement

The status section of `README.md` shall be generated from the slice files and the traceability data, and the gates shall fail when the committed `README.md` has a status section, a link, a `make` target or a command-line option that does not agree with the repository.

## Rationale

The README is the first page that a reader sees. A status that is written by hand becomes wrong when the work continues.

## Acceptance criteria

1. `README.md` has exactly one block that starts with the line `<!-- BEGIN GENERATED: status -->` and ends with the line `<!-- END GENERATED: status -->`. A missing, duplicated or unclosed marker makes the check fail.
2. `cargo run -p atari-harness --bin spec-index` writes the block: one table row for each slice file in `docs/plan/` with the slice ID as a link, the title, the status, and the number of the slice requirements in each matrix state (`tested`, `pending`, `missing`, `not a test requirement`); then one line with the counts of the whole matrix and the number of open items with the status `open`. The program does not change the text outside the block.
3. The `indexes` gate fails when the committed block differs from a new generation.
4. The `references` gate checks `README.md`: each relative link names a file or directory that exists, and each `REQ-`, `OI-` and `SLICE-` ID exists.
5. A gate fails when `README.md` names a `make` target (in the form `make <target>` in a code span or a code block) that is not a target in `Makefile`.
6. A gate fails when `README.md` names a command-line option of the form `--<name>` that the help text of the frontend (`src/cli.rs`) does not contain. Options of other programs in a code span that starts with `cargo` are not checked.
