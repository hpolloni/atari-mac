# REQ-307: Playfield pixel encoding to GTIA

## Requirement

The emulator shall send one 3-bit code to GTIA for each color clock, with the encodings in the table below.

| Code | Lo-res mode | Hi-res mode |
| --- | --- | --- |
| `%000` | Background (`BAK`) | Background (`BAK`) |
| `%001` | Vertical sync | Vertical sync |
| `%010` | Horizontal blank, lo-res | Horizontal blank, lo-res |
| `%011` | Horizontal blank, hi-res | Horizontal blank, hi-res |
| `%100` | `PF0` | Pixel pair `%00` |
| `%101` | `PF1` | Pixel pair `%01` |
| `%110` | `PF2` | Pixel pair `%10` |
| `%111` | `PF3` | Pixel pair `%11` |

## Rationale

GTIA makes the final colors from these codes. GTIA modes use the two low bits of the hi-res codes as raw data (HRM 6.9).

## Acceptance criteria

1. A normal-width mode F line (`DMACTL` = `$22`) has all bytes `$1B`. From position `$30` to position `$CF`, each group of 4 color clocks has the codes `%100`, `%101`, `%110` and `%111`, left to right.
2. The same mode F line with all bytes `$00` has code `%100` at every position from `$30` to `$CF`. A mode 2 line with font data `$00` also has code `%100` at every position from `$30` to `$CF`.
3. A normal-width mode E line has all bytes `$1B`. From position `$30` to position `$CF`, each group of 4 color clocks has the codes `%000`, `%100`, `%101` and `%110`, left to right.
4. On the lines of criteria 1 and 3, positions `$22-$2F` and `$D0-$DD` have code `%000`.
5. In a mode 4 line, a character with name `$81` and font byte `$FF` has code `%111` (`PF3`) on its 4 color clocks (REQ-315).

## Notes

The design document defines how the emulator passes the codes from ANTIC to GTIA.
