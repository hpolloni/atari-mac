# REQ-347: Data of virtual DMA cycles

## Requirement

The emulator shall load the value on the data bus in the same cycle as playfield data for each virtual DMA cycle (cycle 106 or later).

## Rationale

The garbage at the right edge of wide playfields is CPU bus activity. GTIA shows it and it can cause player-playfield collisions.

## Acceptance criteria

1. With `DMACTL` = `$23`, on the first scan line of a mode E line, the data bus value `$A5` in cycle 106 (the virtual `Bitmap` fetch) goes into line buffer byte 47.
2. In the full machine, on the first scan line of a `$1E` line with `DMACTL` = `$23` and `HSCROL` = 2, `STA WSYNC` has its write on cycle 104. The CPU waits on the opcode fetch of the next instruction, `NOP` (`$EA`). The virtual fetch on cycle 107 loads `$EA` into line buffer byte 47.
3. On the first scan line of a `$12` line with `DMACTL` = `$23` and `HSCROL` = 2, the refresh and the virtual `CharacterData` fetch are both on cycle 106. With the value `$5A` on the data bus in cycle 106, positions `$DA-$DD` have the codes `%101`, `%101`, `%110` and `%110`.

## Notes

The floating bus value is a system decision (area `system`). The HRM says that XL and some XE machines have pull-up resistors and that others float.

Criterion 2 needs the full machine, because the machine gives the data bus value of the repeated CPU read to ANTIC. Criterion 3 checks only that ANTIC uses the data bus value of the refresh cycle. The machine selects that value.
