# REQ-315: Character modes 4 and 5

## Requirement

The emulator shall show IR modes 4 and 5 as lo-res multicolor text with 128 characters at the address `(CHBASE & $FC) << 8 | (name & $7F) << 3 | font row`, where each pair of font bits gives one pixel of one color clock.

## Rationale

Many games use mode 4 for graphics tiles.

## Acceptance criteria

1. In a mode 4 line, a character with name `$01` and font byte `$1B` has the codes `%000`, `%100`, `%101` and `%110` on its 4 color clocks, left to right.
2. A character with name `$81` and font byte `$1B` has the codes `%000`, `%100`, `%101` and `%111`.
3. With `CHBASE` = `$E0`, the font fetch for row 0 of a mode 4 character with name `$C1` reads `$E208`.
4. In a normal-width mode 4 line with names `$00` to `$27` and a different row 0 font byte for each name, positions `$30 + 4k` to `$33 + 4k` show the codes of the font byte of name k, for k = 0 to 39.
5. In mode 4, row r (r = 0-7) reads font row r. In mode 5, row r (r = 0-15) reads font row r >> 1.

## Notes

TRN HW-II.A/Character-Display-Instructions and ANTIC-SPEC 6.5 say in the text that data `%10` selects PF2 when name bit 7 is 1. The tables in the same sections and the HRM say that data `%11` selects PF3 when name bit 7 is 1. This requirement follows the HRM.
