# REQ-058: Cyclomatic complexity limit

## Requirement

Each Rust function of the workspace shall have a cyclomatic complexity of at most 15, except the functions on the code baseline, which shall not become more complex.

## Rationale

A function with many paths is hard to read and hard to test. The clippy lint `cognitive_complexity` counts a `match` as one decision, so it does not find a function with a long `match` on the command-line options (the user found one at complexity 63, 2026-11-21).

## Acceptance criteria

1. The complexity of a function is 1, plus 1 for each `if` (also `if let` and `else if`), `while` (also `while let`), `for`, `&&`, `||` and match guard (`if` on a match arm), plus the number of arms of each `match` minus 1. A closure counts in the function that contains it. A nested `fn` is a function of its own.
2. The gate reads each `.rs` file of the workspace that git tracks (`src/`, `tests/`, `benches/`, `build.rs` and the same paths of each crate in `crates/`), also the test code.
3. A function with a complexity above 15 that is not on the code baseline fails the gate. The message gives the file, the line, the function name and the complexity.
4. The code baseline `docs/spec/code-baseline.txt` has one line for each function that is allowed above 15: `complexity`, the file, the function name and the complexity at the time of the line. The function name is `Type::name` for a function in an `impl` block and `name` otherwise.
5. A function on the baseline with a complexity above the baseline value fails the gate. A baseline line that matches no function above 15, or that has a value above the current complexity, fails the gate as stale.
6. The gate runs in `make pre-commit`, in `make check` and in the CI job `Specification`.

## Notes

Project decision: the user asked for this gate on 2026-11-21. The baseline may only become smaller (the rule of `docs/spec/gate-baseline.txt`). The lead decides each line.
