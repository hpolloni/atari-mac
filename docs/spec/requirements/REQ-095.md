# REQ-095: Turbo while the disk drive transfers data

## Requirement

While drive D1: has a disk and takes part in a transfer on the SIO bus, the frontend shall run the emulation in turbo, with the same frame display and audio rules as the turbo of the tape (REQ-082).

## Rationale

A loader that does not use SIOV reads the disk through the POKEY serial port at 19,200 baud, and the SIOV shortcut does not help it. With turbo, it loads in the time that the host needs, and the emulated machine stays exact to the cycle. The tape has the same rule (REQ-082).

## Acceptance criteria

1. The drive takes part in a transfer from the first bit of a command frame for D1: until the last bit of the reply of the drive (REQ-615). A frame that starts while the drive takes part in a transfer, or within 30 frames after the end of the last transfer, runs in turbo.
2. A frame that starts more than 30 frames after the end of the last transfer runs with real-time pacing (REQ-007), unless another turbo rule applies (REQ-080, REQ-082).
3. Without a disk, the SIO bus has no effect on the pacing.
4. In turbo, the frontend shows a frame at least every 100 ms of host time, plays no audio, and does not count this as an underrun (REQ-011).
5. The emulated machine does not depend on turbo: after the same frames and the same key input, the frame buffer and the RAM are the same with turbo and without turbo.
6. The `frontend` log category (REQ-085) gives the cause of the turbo as the disk drive.

## Notes

Project decision (OI-056, decided on 2026-11-21, the same rule as the tape). The 30 frames keep turbo on between the sectors of a load, so that the audio does not start and stop for each sector. With the SIOV shortcut on, a request through SIOV has no transfer on the bus, so it starts no turbo.
