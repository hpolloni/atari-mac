# REQ-306: Blank and sync signals to GTIA

## Requirement

The emulator shall send the horizontal blank code to GTIA during horizontal blank and during all of vertical blank, and shall send the vertical sync code during all of scan lines 251-253 (NTSC) or 275-277 (PAL).

## Rationale

ANTIC has no separate vertical blank signal. It holds horizontal blank active during vertical blank. GTIA uses the vertical sync code to make the vertical sync pulse.

## Acceptance criteria

1. A mode 2 line is on scan lines 40-47. On scan line 41, the code at positions `$00-$21` and `$DE-$E3` is `%011`. A mode A line is on scan lines 60-63. On scan line 61, the code at the same positions is `%010`.
2. With IR = `$41` at scan line 248 (NTSC), every color clock of scan lines 251, 252 and 253 has code `%001`.
3. With IR = `$41` at scan line 248 (PAL), every color clock of scan lines 275, 276 and 277 has code `%001`.
4. With IR = `$41` at scan line 248, every color clock of scan lines 248-250, 254-261 and 0-7 (NTSC) or 248-274, 278-311 and 0-7 (PAL) has code `%010`.
5. With IR = `$02` at scan line 248 and `DMACTL` = `$20`, every color clock of the vertical blank scan lines has code `%011`, except the vertical sync scan lines, which have `%001`.

## Notes

HRM 4.6 (Hi-res last scan line bug) gives PAL vertical sync as scan lines 275-278. HRM 6.2 gives 275-277. This requirement uses HRM 6.2, because that section describes the ANx bus code (OI-012, decided).

The HRM does not give the exact cycles where ANTIC starts and stops horizontal blank on a visible scan line. Project decision: ANTIC sends horizontal blank for horizontal positions outside the visible range `$22-$DD` (HRM 6.2). See `docs/design/antic.md`.
