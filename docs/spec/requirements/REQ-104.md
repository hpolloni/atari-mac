# REQ-104: Read-modify-write double write

## Requirement

The emulator shall execute each read-modify-write instruction as a read of the operand, a write of the unchanged value, and then a write of the result, at the same address.

## Rationale

On the NMOS 6502, the modify cycle is a write cycle that writes back the value just read (HRM 3.6). Fast IRQ acknowledge methods with RMW instructions on `IRQEN` and `IRQST`, and the timing of `INC WSYNC`, need this behavior.

## Acceptance criteria

1. Start: `$0600` = `$41`. `INC $0600` takes 6 cycles. Cycles 1 to 3 read the instruction bytes. Cycle 4 reads `$41` from `$0600`. Cycle 5 writes `$41` to `$0600`. Cycle 6 writes `$42` to `$0600`.
2. The test `single_step_bus_cycles` (REQ-101) passes for all opcodes of `ASL`, `LSR`, `ROL`, `ROR`, `INC` and `DEC` with a memory operand, and for all opcodes of `SLO`, `RLA`, `SRE`, `RRA`, `DCP` and `ISB`. In each case, the last three accesses to the effective address are a read, a write of the value read, and a write of the result.

## Notes

HRM 3.6 describes the difference on the 65C02. The 65C02 is out of scope. This requirement uses only the 6502 part of that text.
