# REQ-422: Collision area

## Requirement

The emulator shall detect collisions only at HPOS `$22-$DD` on scanlines 8-247.

## Rationale

Objects in the blank regions must not set collision bits. Some programs park sprites in the blank regions.

## Acceptance criteria

In all criteria, `GRAFP0` = `GRAFP1` = `$FF`, single width, and the collision registers are clear before the test.

1. With `HPOSP0` = `$1A` (HPOS `$1A-$21`) and `HPOSP1` = `$1C` (HPOS `$1C-$23`), the players overlap only at HPOS `$1C-$21`. `P0PL` and `P1PL` read `$00`.
2. With `HPOSP0` = `$1C` (HPOS `$1C-$23`) and `HPOSP1` = `$20` (HPOS `$20-$27`), the players overlap at HPOS `$20-$23`. `P0PL` reads `$02` and `P1PL` reads `$01`.
3. With `HPOSP0` = `$DA` (HPOS `$DA-$E1`) and `HPOSP1` = `$DE` (HPOS `$DE-$E5`), the players overlap only at HPOS `$DE-$E1`. `P0PL` and `P1PL` read `$00`.
4. With `HPOSP0` = `HPOSP1` = `$80`, and the player data loaded only on scanlines 248-261 and 0-7 (NTSC) or 248-311 and 0-7 (PAL), where ANTIC sends blank codes, `P0PL` and `P1PL` read `$00`.

## Notes

The HRM states that GTIA can detect collisions on scanlines 248-7 when ANTIC fails to start vertical blank because of the hires bug (HRM 6.2). The emulator does not model this case. It uses scanlines 8-247 only (see the open issues in `docs/design/gtia.md`).
