# REQ-420: P/M to playfield collisions

## Requirement

The emulator shall set bit k of `PnPF` or `MnPF` when player n or missile n is active at a color clock where playfield k is present.

## Rationale

Games use the collision registers for hit tests with the playfield.

## Acceptance criteria

In all criteria, the objects and the playfield overlap in HPOS `$22-$DD` of scanlines 8-247, the collision registers are clear before the test (`HITCLR`), and all collision registers that the criterion does not name read `$00` after the frame.

1. On a low resolution line, player 0 on a `PF1` pixel (code `%101`) sets `P0PF` to `$02`. Missile 3 on a `PF3` pixel (code `%111`) sets `M3PF` to `$08`.
2. Player 0 and missile 0 on background pixels (code `%000`) set no collision bit.
3. On a hires line (last horizontal blank code `%011`), player 0 on code `%101`, `%110` or `%111` sets `P0PF` to `$04`. Player 0 on code `%100` sets no bit.
4. With `PRIOR` = `$40` or `$C0`, player 0 and missile 0 on pixels with the values 1-15 set no bit.
5. With `PRIOR` = `$80`, player 0 over a full pixel with value 4, 5, 6, 7, 12, 13, 14 or 15 sets `P0PF` to `1 << (value AND 3)`. Player 0 over a full pixel with value 0-3 or 8-11 sets no bit.
6. With `PRIOR` = `$04` (playfield over players) and all 9 color registers = `$00`, player 0 on a `PF0` pixel sets `P0PF` to `$01`.
