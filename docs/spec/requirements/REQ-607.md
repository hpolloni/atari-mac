# REQ-607: Cartridge state on reset

| Field | Value |
| --- | --- |
| Status | Draft |
| Priority | Should |

## Requirement

The emulator shall keep the bank state of a bank-switched cartridge when the user presses the RESET key, and shall select bank 0 with the cartridge enabled on a cold reset.

## Rationale

The cartridge port does not have the computer reset signal, so a cartridge cannot see a warm reset. Software that works on real hardware has startup code in all banks for this reason.

## Acceptance criteria

The test image uses the bank pattern: each byte of bank `k` holds `k`. The test reads `$A000` and `TRIG3` with no side effects, and the CPU executes no instruction between the action and the read.

1. With a MaxFlash 1Mbit cartridge, an access to `$D505` and then a press of the RESET key: a read of `$A000` gives `$05`.
2. With a MaxFlash 1Mbit cartridge, an access to `$D510` and then a press of the RESET key: the cartridge does not map `$A000-$BFFF` (RD5 negated), and `TRIG3` reads `$00`.
3. With a MaxFlash 1Mbit cartridge, an access to `$D515` (bank 5, disabled) and then a cold reset (power off and on): a read of `$A000` gives `$00`, and `TRIG3` reads `$01`.
4. Criterion 3 also passes with a MaxFlash 8Mbit cartridge and an access to `$D585` (bank 5, disabled).

## Notes

On real hardware, a cartridge without reset circuitry starts in an unknown bank. Bank 0 is a project decision. To verify: the start bank that other emulators use for CAR type 42.
