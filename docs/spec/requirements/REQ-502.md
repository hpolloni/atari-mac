# REQ-502: Initialization mode

| Field | Value |
| --- | --- |
| Status | Draft |
| Priority | Must |
| Area | POKEY: audio, timers, keyboard, interrupts, serial port |
| Source | HRM 5.2 Initialization (Initialization mode); HRM 5.5 Noise generators (Initialization behavior) |
| Verification | Test |
| Depends on | REQ-501 |

## Requirement

While `SKCTL` bits 0 and 1 are both 0, the emulator shall hold in reset the 15 kHz clock, the 64 kHz clock, the four polynomial counters, the serial input and output state machines, the `SEROUT` pending flag and the keyboard scan.

## Rationale

The OS writes `SKCTL` = `$00` and then `$03` to start POKEY. Software uses the exit from initialization mode to set the phase of the 15 kHz clock in the scanline.

## Acceptance criteria

1. With `SKCTL` = `$00`, `IRQEN` = `$01`, `AUDF1` = `$00` and `AUDCTL` = `$00` (and again with `AUDCTL` = `$01`), and an `STIMER` write on cycle T, `IRQST` bit 0 reads 1 and the timer 1 counter (test accessor) does not change from cycle T+4 to cycle T+10000.
2. With `SKCTL` = `$00`, `AUDCTL` = `$40`, `AUDF1` = `$00`, `IRQEN` = `$01` and an `STIMER` write on cycle T, `IRQST` bit 0 reads 0 from cycle T+8.
3. Start state: `SKCTL` = `$03`, `AUDCTL` = `$01`, `AUDF1-4` = `$11`, `$22`, `$33`, `$44`, `AUDC1-4` = `$A1`, `$A2`, `$A3`, `$A4`, `IRQEN` = `$01` with `IRQST` bit 0 latched, `KBCODE` = `$3F` (A key registered) and `SERIN` = `$43` (one received frame). A write of `SKCTL` = `$00` on cycle I does not change `IRQEN`, `IRQST`, `KBCODE`, `SERIN`, `AUDF1-4`, `AUDC1-4`, `AUDCTL`, the four timer counters or the four channel output flip-flops. The test compares the values on cycle I-1 with the values on cycles I+1 and I+1000.
4. With `SKCTL` = `$23`, `AUDCTL` = `$28`, `AUDF3` = `$28` and `AUDF4` = `$00`, the test writes `SEROUT` = `$4F`. After the load (`IRQST` bit 4 = 0 with `IRQEN` = `$10`), it writes `SEROUT` = `$55`. Then it writes `SKCTL` = `$00` before the end of the first frame, and `SKCTL` = `$23` 1000 cycles later. In the next 5000 cycles, `take_serial_byte` gives no byte, SIO DATA OUT does not change, and `IRQST` bit 3 reads 0.
5. With `SKCTL` = `$03`, a `POTGO` write and no paddle on input 0, when `POT0` reads 10, a write of `SKCTL` = `$00` keeps `POT0` at 10 and `ALLPOT` bit 0 at 1 for 10 x 114 cycles.
6. After a write of `SKCTL` = `$00` on cycle I (from `SKCTL` = `$03`), each read of `RANDOM` from cycle I+9 to cycle I+1000 returns `$FF`. This is true with `AUDCTL` = `$00` and with `AUDCTL` = `$80`.
7. With `SKCTL` = `$00`, `IRQEN` = `$40` and the A key down for 300 x 114 cycles, `IRQST` bit 6 reads 1, `SKSTAT` bit 2 reads 1 and `KBCODE` does not change.
8. With `SKCTL` = `$20` (initialization mode, input clock channel 4), `AUDCTL` = `$28`, `AUDF3` = `$28`, `AUDF4` = `$00` and `IRQEN` = `$20`, a frame for `$43` with 94-cycle bits on SIO DATA IN does not change `SERIN`. `IRQST` bit 5 and `SKSTAT` bit 1 read 1 during the frame and for 1000 cycles after it.

## Notes

The HRM lists the circuits that initialization mode resets and the circuits that it does not reset. Criterion 2 follows from the HRM statement that only the 15 kHz and 64 kHz timers stop. REQ-513 criterion 3 checks the 4-bit and 5-bit counters in initialization mode.

The HRM states that the shift register of `RANDOM` needs 9 more cycles (18 in total) to clear fully. A restart before that time works, but not all bits are reset.
