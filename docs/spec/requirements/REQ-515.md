# REQ-515: IRQEN and IRQST

## Requirement

The emulator shall latch an interrupt event into `IRQST` (bit = 0) only when its `IRQEN` bit is 1, shall set an `IRQST` bit to 1 when software writes 0 to its `IRQEN` bit, and shall assert the IRQ output while any of `IRQST` bits 0-2 and 4-7 is 0.

## Rationale

The OS IRQ handler reads `IRQST` and clears each source through `IRQEN`. The keyboard, the BREAK key, the serial port and the timers all use this logic.

## Acceptance criteria

1. With `AUDCTL` = `$40`, `AUDF1` = `$00`, `IRQEN` = `$01` and an `STIMER` write on cycle T, `IRQST` reads `$F6` and `irq()` returns true on cycle T+8.
2. After criterion 1, a write of `IRQEN` = `$00` on cycle X makes `IRQST` read `$F7` and `irq()` return false from cycle X+1.
3. With `AUDCTL` = `$00`, `AUDF1` = `AUDF2` = `$00` and `IRQEN` = `$03`, after both bits latch (`IRQST` = `$F4`), a write of `IRQEN` = `$02` makes `IRQST` read `$F5`, and `irq()` stays true. A later write of `IRQEN` = `$00` makes `IRQST` read `$F7` and `irq()` return false from the next cycle.
4. Two instances get the same writes and inputs for 10000 cycles (the setup of criterion 1). One instance also reads `IRQST` on each cycle. The register reads (with `peek`), the test accessor values and the samples of the two instances are the same.
5. With `AUDCTL` = `$00`, `AUDF1` = `$00` and `IRQEN` = `$00`, timer 1 fires on cycles E and E+28. A write of `IRQEN` = `$01` on cycle E+1 makes `IRQST` bit 0 read 1 on cycles E+1 to E+27 and 0 on cycle E+28.

## Notes

The PIA can also assert the IRQ line of the CPU. The machine combines the two sources. The CPU teammate specifies the delay of 2-3 cycles from `IRQST` to the start of the IRQ sequence (HRM 5.7 Interrupt timing).

Bit 3 of `IRQST` is not latched. REQ-516 specifies it.
