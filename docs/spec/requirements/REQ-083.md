# REQ-083: Speed statistics

## Requirement

When the command line has `--stats`, the frontend shall write one line of speed statistics to standard error after each second of host time.

## Rationale

The user must see why the emulation runs slow or fast: the emulation is too slow for the host, the pacing is wrong, the window update waits, or turbo is on or off at the wrong time.

## Acceptance criteria

1. With `--stats`, the frontend writes one line to standard error after each 1.0 s of host time, from the first frame. Each line has this format, with single spaces:
   `stats: frame <n> fps <f> speed <p>% shown <s> emu <m> ms turbo <on|off> motor <on|off|-> underruns <u>`
2. `<n>` is the number of frames that ran since the start. `<f>` is the number of frames that ran in the last second of host time, divided by the length of that second in seconds, with one decimal.
3. `<p>` is `<f>` divided by the frame rate of the video standard (59.92 for NTSC, 49.86 for PAL, REQ-201), times 100, rounded to an integer.
4. `<s>` is the number of frames that the window showed in the last second. It is `0` with `--headless`.
5. `<m>` is the mean host time of the emulation of one frame in the last second, in milliseconds, with two decimals. It does not include the wait of the pacing or the window update.
6. `turbo` is `on` when the last frame of the second ran in turbo (REQ-080, REQ-082), else `off`. `motor` is the cassette motor at the last frame (REQ-641): `on`, `off`, or `-` when no tape is inserted.
7. `<u>` is the number of audio underruns in the last second (REQ-011). It is `0` with `--headless`.
8. Without `--stats`, the frontend writes no statistics line.
9. `--help` lists `--stats`.

## Notes

Project decision (2026-11-21, SLICE-09). The HRM does not cover it.

A test uses a fake host clock, so the criteria do not depend on the speed of the host.
