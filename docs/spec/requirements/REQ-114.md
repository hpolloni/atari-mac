# REQ-114: BRK instruction

## Requirement

The emulator shall execute `BRK` in 7 cycles as an interrupt sequence that pushes the return address and `P` with bit 4 set, sets `I`, and loads `PC` from `$FFFE`.

## Rationale

The BRK instruction is the same as an IRQ, except for the B flag on the stack (HRM 3.4). Debuggers and some programs use `BRK`.

## Acceptance criteria

1. Start: `PC` = `$8B82`, `$8B82` = `$00`, `S` = `$51`, `P` = `$6A`, `$FFFE` = `$34`, `$FFFF` = `$12`. `BRK` takes 7 cycles. It writes `$8B` to `$0151`, `$84` to `$0150` and `$7A` to `$014F`, in this order.
2. After the `BRK` of criterion 1, `PC` = `$1234`, `S` = `$4E` and `I` = 1. `N`, `V`, `D`, `Z` and `C` keep their values.
3. The test `single_step_brk` runs all cases of the SingleStepTests 6502 file `00.json`. The final registers, the RAM bytes and the `cycles` list agree with the file.

## Notes

The HRM does not state the return address (the address of `BRK` + 2) or the change of `I`. MCS6500-PRG 9.11 gives the return address `BRK` + 2. MCS6500-PRG 3.2 says that the CPU sets `I` during interrupt commands, and lists `BRK` as an instruction that changes `I`. The SingleStepTests data agrees with both. MCS6500-PRG 9.11 also says that `BRK` changes no flags. This requirement follows MCS6500-PRG 3.2 and the SingleStepTests data.

MCS6500-HW App-A (A.5.4) and NMS fetch-stack-software-interrupts give the 7 cycles: the opcode fetch, a read of `PC` + 1, the 3 stack writes, and the reads of `$FFFE` and `$FFFF`.
