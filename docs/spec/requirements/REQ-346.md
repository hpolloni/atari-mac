# REQ-346: Hi-res mode at the start of vertical blank

## Requirement

The emulator shall, when IR holds a hi-res mode (2, 3 or F) at the start of vertical blank and playfield DMA is enabled, set AN2 = 1 in the codes to GTIA in the active part of the vertical blank scan lines, so that ANTIC sends `%111` instead of `%011` and `%101` instead of `%001`.

## Rationale

This bug opens the bottom border on hardware. Some demos use it. If playfield DMA stays on through vertical sync, the display rolls.

## Acceptance criteria

1. A mode F line is on scan line 247 (NTSC), so IR = `$0F` at scan line 248. `DMACTL` = `$22` through vertical blank. Position `$80` has code `%111` instead of `%011` on scan lines 248-250, 254-261 and 0-7, and code `%101` instead of `%001` on scan lines 251-253. Positions `$00-$21` keep code `%011` on scan lines 248-250 and 254-261.
2. In the same state on PAL, position `$80` has code `%101` on scan lines 275-277.
3. With IR = `$41` at scan line 248 and `DMACTL` = `$22`, position `$80` has code `%010` on scan lines 248-250 and code `%001` on scan lines 251-253.
4. In the state of criterion 1, a write of `$20` to `DMACTL` on scan line 250: position `$80` has code `%001` on scan lines 251-253 and code `%011` on scan lines 254-261.
5. With IR = `$0F` at scan line 248 and `DMACTL` = `$20`, position `$80` has code `%011` on scan lines 248-250 and code `%001` on scan lines 251-253.
6. In the state of criterion 1 with `DMACTL` = `$22`, positions `$30-$CF` have code `%111` on scan line 248, and positions `$22-$2F` and `$D0-$DD` have code `%011`. With `DMACTL` = `$21`, the `%111` positions are `$40-$BF`.

## Notes

HRM 4.6 says "whenever bits 0-1 of DMACTL[3:2] are other than 00". HRM 6.2 says "Playfield DMA is enabled". This requirement uses `DMACTL` bits 1-0.

HRM 6.2 (Figure 14) says that ANTIC sends `%111` instead of `%011` on the vertical blank scan lines and `%101` instead of `%001` on the vertical sync scan lines, in the active region. HRM 6.2 (Opening the vertical border; Effects on horizontal sync) gives the region as the playfield region of the current width, inside the display bounds (OI-015). The wide region `$2C-$DD` is inferred from the left clip in HRM 6.2.

HRM 4.6 gives PAL vertical sync as scan lines 275-278. HRM 6.2 gives 275-277. This requirement uses HRM 6.2, as REQ-306 does (OI-012, decided).
