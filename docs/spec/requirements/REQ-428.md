## Requirement

When `PRIOR` bits 6-7 are not `%00`, the emulator shall make each 4-bit pixel from bits AN1-AN0 of two consecutive color clocks that start at an even HPOS, with the first color clock as bits 3-2, and shall ignore AN2 and the hires state.

## Rationale

GTIA modes 9, 10 and 11 (GRAPHICS 9, 10 and 11) use these 4-bit pixels. Each pixel is two color clocks wide, which gives 80 pixels at normal width.

## Acceptance criteria

In all criteria, `PRIOR` = `$40` and `COLBK` = `$00`, except where the criterion states other values.

1. With an ANTIC mode F line at normal width, `HSCROL` = 0 and first byte `$1F`, HPOS `$30-$31` show `$01` and HPOS `$32-$33` show `$0F`.
2. With an ANTIC mode E line at normal width, `HSCROL` = 0 and all bytes `$FF` (code `%110` at each color clock), HPOS `$30-$CF` show `$0A`.
3. In a GTIA unit test, AN1-AN0 values `%00`, `%00`, `%01`, `%11`, `%11`, `%00` at HPOS `$30-$35` (as with an odd `HSCROL` value) give `$00` at HPOS `$30-$31`, `$07` at HPOS `$32-$33` and `$0C` at HPOS `$34-$35`.
4. The code pairs (`%000`, `%101`) and (`%100`, `%101`) at an even HPOS and the next HPOS both show `$01`.
5. After the horizontal blank code `%011`, with `COLBK` = `$90` and `COLPF1` = `$0E`, the code pair (`%110`, `%110`) shows `$9A` in all four columns. Player 0 on this pixel sets no bit in `P0PF`.

## Notes

Source: project decision for the even HPOS. The HRM states that the pairs are fixed relative to horizontal blank and do not move with `HSCROL`. All playfield widths start at an even HPOS (`$20`, `$30`, `$40`), so the project aligns the pairs to even HPOS values.
