# REQ-627: Status command

## Requirement

In reply to Status (`$53`), the disk drive shall send the four-byte status frame in the table, and shall ignore AUX1 and AUX2.

| Byte | Bit | Value |
| --- | --- | --- |
| 0 | 7 | 1 if the image has 1040 sectors of 128 bytes (ED) |
| 0 | 6 | 0 (not double-sided) |
| 0 | 5 | 1 if the image has 256-byte sectors (DD) |
| 0 | 4 | 0 (motor not running) |
| 0 | 3 | 1 if the last command failed because the disk is write-protected |
| 0 | 2 | 0 |
| 0 | 1 | 1 if the last data frame from the computer had an error |
| 0 | 0 | 1 if the drive sent NAK for the last command frame |
| 1 | 7 | 0 if no disk is inserted, else 1 |
| 1 | 6 | 0 if the inserted disk is write-protected, else 1 |
| 1 | 5-0 | 1 |
| 2 | all | `$E0` (format timeout) |
| 3 | all | `$00` |

## Rationale

DOS reads the status to find the density of the disk and the cause of an error. The second byte is the inverted FDC status, so a 0 bit shows an error.

## Acceptance criteria

Each criterion gives the four bytes of the status frame. The drive state is the state after insertion of the image, with no command before the Status command unless the criterion gives one.

1. SD image (720 x 128), write enabled: `00 FF E0 00`.
2. ED image (1040 x 128): `80 FF E0 00`.
3. DD image (720 x 256): `20 FF E0 00`.
4. Image of 16384 sectors of 128 bytes: `00 FF E0 00`.
5. SD image, write-protected: `00 BF E0 00`.
6. No image: `00 7F E0 00`.
7. SD image. Read of sector 0 gets NAK (REQ-628). The next Status gives `01 FF E0 00`. A second Status then gives `00 FF E0 00`.
8. SD image. Read of sector 0 gets NAK. Then Read of sector 1 completes. The next Status gives `00 FF E0 00`.
9. Status with AUX1 = `$FF` and AUX2 = `$FF` (`31 53 FF FF 84`) gives the same frame as Status with AUX1 = AUX2 = `$00`, for the images of criteria 1, 3 and 6.

## Notes

The status frame shows the result of the command before the Status command. A good Status command then clears bits 0-3 of byte 0. To verify: the time when a real 1050 clears these bits.

The HRM is not consistent about the write-protect bit of byte 0. Table 44 gives bit 3 ("failed due to write protected disk"). HRM 10.15 refers to "bit 4 of drive status". This requirement uses Table 44.

The HRM gives the format timeout `$E0` for the 810. HRM 10.2 does not recommend a value lower than `$E0`.

Bit 4 (motor running) is 0, because the emulator has no motor model. This is a project decision.

SIO-810 1.3.4 and TRN OS-5/Resident-Device-Handler-Vectors give the same bits 0-4 of byte 0 as HRM Table 44.

SIO-810 1.3.4 says that bytes 2 and 3 are one 16-bit timeout in seconds, `$00E0` (224 seconds). TRN OS-5/Resident-Device-Handler-Vectors says that byte 2 is a timeout in seconds. The HRM says that byte 2 is the format timeout in units of 64 vertical blanks, and that byte 3 is not used. This requirement follows the HRM. The bytes are the same (`E0 00`).

TRN OS-5/Resident-Device-Handler-Vectors says that byte 1 is the status register of the FDC. The HRM says that byte 1 is the inverted FDC status. SIO-810 1.3.4 also says that the value is inverted. This requirement follows the HRM.
