# REQ-093: Boot with BASIC off from the command line

## Requirement

When the command line has `--no-basic`, the frontend shall hold OPTION at the power-on cold reset, so that the OS boots with BASIC off (REQ-006).

## Rationale

A program that uses the RAM at `$A000-$BFFF` needs BASIC off. On the real computer, the user holds OPTION at power-on, and holds START and OPTION for such a tape. A tape of 46,848 bytes of data does not fit in the RAM below `$A000` with BASIC on.

## Acceptance criteria

1. With `--no-basic`, the frontend holds OPTION from the power-on cold reset until frame 60, the same frames as the START hold of REQ-081 criterion 3.
2. With `--no-basic` and no media, after 180 frames, a write of `$5A` to `$A000` and a read give `$5A` (RAM). Without `--no-basic`, the read gives byte `$0000` of the BASIC ROM.
3. With `--no-basic` and `--cas`, the frontend holds START and OPTION until frame 60. The boot test tape of REQ-643 boots with `--auto-return` (REQ-092), and after the boot, a write of `$5A` to `$A000` and a read give `$5A`.
4. With `--no-basic` and `--disk`, the frontend holds OPTION until frame 60, and the disk boots as in REQ-012.
5. `--no-basic` together with `--bas` gives exit code 2 and a message that names both options. `--no-basic` with `--xex` is accepted and has no other effect, because `--xex` already holds OPTION.
6. `--help` lists `--no-basic`.

## Notes

Project decision of the user (2026-11-21). The F10 cold reset does not hold OPTION. The user holds F4 (OPTION) during F10, as before.
