# REQ-620: Data frame checksum error

## Requirement

When a data frame from the computer has a checksum error, the disk drive shall send NAK (`$4E`), shall not change the disk image, and shall send no Complete or Error byte.

## Rationale

The OS then sends the command again. If the drive wrote the bad data, the disk would be damaged.

## Acceptance criteria

All criteria use the SD test image of REQ-619 (each byte of sector `n` holds `n & $FF`) and NTSC timing.

1. Put sector 5 (`31 50 05 00 86`). The computer sends 128 bytes of `$5A` and the checksum `2C` (the checksum of the data is `2D`). The drive sends `41`, then `4E`, and then no byte in the 178,977 machine cycles (100 ms) after the end of the `4E` byte.
2. After criterion 1, sector 5 holds 128 bytes of `$05`, and the image reports no change (REQ-637).
3. After criterion 1, the next Status command gives the status frame `02 FF E0 00` (byte 0 bit 1 = 1, REQ-627).

## Notes

The HRM states that real drives differ. Some drives send NAK, and some drives stop the command with no reply. This emulator sends NAK.
