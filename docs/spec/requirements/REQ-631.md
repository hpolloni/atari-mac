# REQ-631: Write-protected images

## Requirement

When the inserted image is write-protected, the disk drive shall reply to Put, Write and Format with Error (`$45`) after the normal ACK bytes, and shall not change the image.

## Rationale

The user can protect an image against changes, as with the write-protect notch of a real disk. The drive finds the error only when it accesses the disk, so it reports Error, not NAK.

## Acceptance criteria

The test image is the SD test image of REQ-619 (each byte of sector `n` holds `n & $FF`), write-protected. The computer sends each data frame with its checksum (REQ-616).

1. Put sector 5 with 128 bytes of `$5A`: the drive sends `41`, receives the data frame, sends `41`, then `45`. Sector 5 then holds 128 bytes of `$05`.
2. Write sector 5 with 128 bytes of `$5A`: the drive sends `41`, receives the data frame, sends `41`, then `45`. Sector 5 then holds 128 bytes of `$05`.
3. Format `$21`: the drive sends `41`, `45`, 128 bytes of `$FF` and `FF`. The image still has 720 sectors, and sector 5 holds 128 bytes of `$05`.
4. Format `$22`: the drive sends `41`, `45`, 128 bytes of `$FF` and `FF`. The image still has 720 sectors.
5. After the failed Put of criterion 1, Status gives the frame `08 BF E0 00`.
6. After criteria 1 to 4, the image reports no change (REQ-637).

## Notes

To verify: whether a real 1050 also sets drive status bit 2 ("unsuccessful PUT operation") for a write-protect error.

SIO-810 1.4.2 says that the 810 sends ACK after the command frame and ERR after the data frame for a write to a write-protected disk. SIO-810 1.2.4 says that a write-protected disk is not written or formatted.
