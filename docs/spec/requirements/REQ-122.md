# REQ-122: NMI hijack of IRQ and BRK sequences

## Requirement

The emulator shall let an NMI that arrives during an IRQ or `BRK` sequence take over that sequence or be lost, with the timing of HRM Figure 2.

## Rationale

An NMI can hijack a `BRK` sequence, so that the NMI vector runs with bit 4 set on the stack (HRM 3.4). On the Atari, this occurs when a `BRK` starts near cycles 4-8 of a scan line with a DLI or VBI.

## Acceptance criteria

In these criteria, the NMI line goes high in cycle N and stays high. An IRQ sequence starts in cycle S. The IRQ handler starts with `LSR abs` (6 cycles).

1. S = N-5: the IRQ sequence (cycles S to S+6) reads `$FFFE` and `$FFFF`. The `LSR abs` runs in cycles N+2 to N+7. The NMI sequence starts in cycle N+8.
2. S = N-4: the IRQ sequence reads `$FFFE` and `$FFFF`. The NMI handler does not run for this edge: the CPU makes no read of `$FFFA` in the next 1,000 cycles.
3. For each S from N-3 to N+1: the sequence that starts in cycle S pushes `P` with bit 4 = 0, reads `$FFFA` in cycle S+5 and `$FFFB` in cycle S+6, and makes no read of `$FFFE`. The CPU reads `$FFFA` only once in the next 1,000 cycles.
4. A `BRK` starts in cycle S instead of the IRQ sequence. For S = N-5 and S = N-4, the results are those of criteria 1 and 2. For each S from N-3 to N+1, the sequence reads `$FFFA` and `$FFFB`, and the pushed `P` has bit 4 = 1.

## Notes

HRM Figure 2 uses the ANTIC NMI at cycle 8. It shows that the NMI is lost when the IRQ sequence starts on cycle 4, and that the NMI takes over the sequence when it starts on cycle 5 or later. HRM 4.8 says that an IRQ that starts at cycles 5-9 can be taken over. The criteria use N = 8 to convert these cycles. HRM 3.4 also says that the BRK effect occurs when a BRK begins at cycles 4-8. For cycle 4, this text does not agree with Figure 2. The emulator follows Figure 2, because the HRM says that the BRK timing is exactly the same as the IRQ timing.
