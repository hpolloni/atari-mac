# REQ-433: Mode 10 background anomaly with low resolution modes

## Requirement

In GTIA mode 10, the emulator shall show the background color for a playfield pixel whose second color clock has ANx code `%000`. In the border, a pixel keeps the color of REQ-430 criterion 3 (HRM 6.9).

## Rationale

The HRM states that the `BAK` code mutes the playfield for the whole pixel when it is the second half. Programs that use mode 10 with ANTIC mode E show this.

## Acceptance criteria

In all criteria, `PRIOR` = `$80`, `COLBK` = `$90`, `COLPF0` = `$50` and `COLPM0` = `$10`.

1. The code pair (`%101`, `%000`) at an even HPOS and the next HPOS (ANTIC mode E bits `%10` then `%00`) gives a pixel that shows `$90`, not `$50`.
2. The code pair (`%101`, `%100`) (ANTIC mode F bits `%0100`) gives a pixel that shows `$50`.
3. The code pair (`%000`, `%100`) gives a pixel that shows `$10` (pixel value 0, player 0 color).

## Notes

GTIA-SPEC 3.0 says that in the 9 color-lum mode the ANx code `%000` gives the background color. The HRM says that the code `%000` gives the background color only as the second color clock of a pixel, and gives the data bits `%00` as the first color clock (criterion 3). This requirement follows the HRM.
