# REQ-106: Branch timing

| Field | Value |
| --- | --- |
| Status | Draft |
| Priority | Must |
| Area | CPU (6502C) |
| Source | HRM 3.3 Cycle timing (Crossing page boundaries) |
| Verification | Test |
| Depends on | REQ-101 |

## Requirement

The emulator shall take 2 cycles for a branch that is not taken, 3 cycles for a taken branch to the same page, and 4 cycles for a taken branch to a different page.

## Rationale

Branch timing sets the timing of most delay loops and display kernels.

## Acceptance criteria

1. Start: `C` = 0. `BCC $80C0` at `$80FE` takes 4 cycles. The 4 reads are at `$80FE`, `$80FF`, `$8100` and `$81C0`. The next opcode fetch is at `$80C0`. The page of the target is compared with the page of the next instruction (`$8100`).
2. Start: `Z` = 1. `BEQ $8110` at `$80FE` takes 3 cycles. The 3 reads are at `$80FE`, `$80FF` and `$8100`. The next opcode fetch is at `$8110`.
3. Start: `C` = 1. `BCC $80C0` at `$80FE` takes 2 cycles. The next opcode fetch is at `$8100`.
4. For the 8 branch opcodes (`$10`, `$30`, `$50`, `$70`, `$90`, `$B0`, `$D0`, `$F0`), the test `single_step_bus_cycles` (REQ-101) passes.
