# REQ-319: Display list instruction fetch

## Requirement

The emulator shall fetch one display list instruction byte into the instruction register (IR) on cycle 1 of the first scan line of each mode line, from the address in `DLISTL`/`DLISTH`, and then increment that address.

## Rationale

The display list controls the full playfield. The OS and all graphics software use it.

## Acceptance criteria

1. With `DMACTL` = `$22`, `out.dma` is `DisplayList` only on cycle 1 of the first scan line of each mode line. For a mode 2 line on scan lines 40-47, the fetch occurs on scan line 40 and on no other scan line of the mode line.
2. After the fetch, IR in the debug state is the fetched byte, and the display list address is one higher.
3. For `$42 $00 $40` at `$1000`, the fetch on cycle 1 reads `$1000`, the `DisplayListAddress` fetch on cycle 6 reads `$1001`, the fetch on cycle 7 reads `$1002`, and the next instruction fetch reads `$1003`.
4. ANTIC uses IR bit 7 as the DLI bit (REQ-332), bit 6 as LMS (REQ-323), bit 5 as vertical scroll (REQ-328), bit 4 as horizontal scroll (REQ-327) and bits 3-0 as the mode (REQ-312, REQ-320, REQ-321).
5. A mode 2 line is on scan lines 40-47. A write of `$00` to `DLISTL` and `$30` to `DLISTH` on scan line 44 makes the instruction fetch on scan line 48 read `$3000`.

## Notes

ANTIC does not store the start address of the display list. The display list must loop or the CPU must restart it.
