# REQ-415: Vertical delay

| Field | Value |
| --- | --- |
| Status | Draft |
| Priority | Should |
| Area | GTIA, color palette, joystick and paddle inputs |
| Source | HRM 6.5 Player/missile graphics (Vertical delay); HRM 14.3 GTIA registers (VDELAY) |
| Verification | Test |
| Depends on | REQ-414 |

## Requirement

When a bit of `VDELAY` is 1, the emulator shall accept DMA data for the related object only on odd scanlines.

## Rationale

Programs use `VDELAY` to move a two-line resolution sprite down by one scanline.

## Acceptance criteria

In all criteria, P/M DMA gives a byte for each object on each scanline 8-247, the byte for scanline s differs from the byte for scanline s - 1, and `GRACTL` = `$03`.

1. For each bit b of `VDELAY`, with only bit b set: on each even scanline 10-246, the object of bit b (bits 0-3: missiles 0-3, bits 4-7: players 0-3) shows the byte of the scanline before, and all other objects show the byte of their own scanline.
2. With `VDELAY` = `$10`, `GRACTL` = `$02` and one-line P/M DMA, each even scanline 2k in 10-246 shows the player 0 byte of scanline 2k - 1, and each odd scanline shows its own byte.
3. With `VDELAY` = `$10`, `HPOSP0` = `$80` and a player 0 DMA byte of `$00`, a CPU write of `$80` to `GRAFP0` in horizontal blank of an even scanline makes HPOS `$80` of that scanline show `COLPM0`.
4. With `VDELAY` = `$00`, each scanline shows its own DMA byte for all objects.
