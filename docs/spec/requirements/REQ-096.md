# REQ-096: Command-line syntax errors

## Requirement

The frontend shall reject a command line that is not valid before the machine starts, with exit code 2 and a message on standard error that names the argument.

## Rationale

A mistyped option must not start the machine with settings that the user did not ask for.

## Acceptance criteria

1. An argument that is not an option of `--help` and not the value of an option gives the message `unknown argument "<argument>"`. This is also true for an option with `=` and a value (for example `--os=file` or `--pal=1`), for two short options in one argument (for example `-hx`), for `--` and for an empty argument.
2. An option that takes a value, as the last argument, gives the message `<option> needs a value`. The next argument is the value of the option, also when it starts with `-`.
3. A number option (`--frames`, `--trace-from`, `--trace-frames`) with a value that is not a decimal number (digits only, with an optional leading `+`) gives the message `<option> needs a number, not "<value>"`.
4. `--scale` with a value outside 1 to 8 gives the message `--scale must be 1 to 8, not <value>`.
5. Each message is on one line of standard error, with the prefix `atari-mac: ` and the suffix ` (see --help)`. The emulator writes nothing to standard output and opens no window.
6. When the command line has more than one error, the message is for the first error from the left.

## Notes

Project decision: the user asked on 2026-11-22 for requirements for the rules of the parser that no requirement stated. The rules are the behavior of the parser on that date (commit 46f8c65).
