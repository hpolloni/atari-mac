# REQ-338: VCOUNT

| Field | Value |
| --- | --- |
| Status | Draft |
| Priority | Must |
| Area | ANTIC |
| Source | HRM 4.10 VCOUNT (including End-of-frame anomaly); HRM 14.6 ANTIC registers (VCOUNT) |
| Verification | Test |
| Depends on | REQ-304 |

## Requirement

The emulator shall return bits 8-1 of the vertical counter in `VCOUNT`, where the counter shows the number of the next scan line from cycle 111 of each scan line.

## Rationale

Many programs wait for a scan line with `VCOUNT`. Software uses its maximum value to identify NTSC or PAL. Tarzan of the Apes needs the new value before the P/M DMA of the next scan line (HRM 4.16).

## Acceptance criteria

1. On each scan line N except the last scan line of the frame, reads of `VCOUNT` on cycles 0-110 return N >> 1, and reads on cycles 111-113 return (N + 1) >> 1.
2. On scan line 7, a read on cycle 110 returns `$03`, and reads on cycles 111, 112 and 113 return `$04`.
3. The first read that returns `$7C` is on cycle 111 of scan line 247. This is 13 cycles before cycle 10 of scan line 248.
4. On the last scan line of the frame, a read on cycle 110 returns `$82` (NTSC) or `$9B` (PAL), a read on cycle 111 returns `$83` (NTSC) or `$9C` (PAL), and reads on cycles 112 and 113 return `$00`.
5. In one NTSC frame, the reads return every value from `$00` to `$83`, and `$83` on exactly one cycle. In one PAL frame, the reads return every value from `$00` to `$9C`, and `$9C` on exactly one cycle.

## Notes

HRM 4.10 says the new value is seen starting on cycle 111. HRM 14.6 says that `VCOUNT` increments on cycle 110. These agree if the increment occurs during cycle 110 and reads see it from cycle 111. The note under HRM Figure 6 says "cycle 100 or later". This requirement treats that as an error in the HRM.
