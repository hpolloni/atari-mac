# REQ-027: Requirement traceability

## Requirement

Each requirement with the verification method `Test` shall have at least one test that names the requirement ID in a `/// Verifies REQ-NNN` documentation comment on a `#[test]` function. Until the work package that plans the requirement is `Done`, the test can be ignored with the reason `planned: SLICE-NN`. When the work package or the slice that plans the requirement is `Done`, at least one of these tests shall run (not be ignored).

## Rationale

Traceability shows which requirements are tested.

## Acceptance criteria

1. `crates/harness/tests/traceability.rs` `finished_packages_have_running_tests` fails if a `Test` requirement of a `Done` package or slice has no test that runs.
2. The same test fails if a `Test` requirement that is not withdrawn has no test, ignored or not.
3. The same test fails if a `Verifies` comment names a requirement that does not exist or that is withdrawn, or if the comment is not on a `#[test]` function.
4. The same test writes `target/traceability.md`: each requirement that is not withdrawn, with its slice and package, its state (`tested`, `pending`, `missing` or `not a test requirement`) and its tests.
5. The same test fails if an ignored test has a reason other than `planned: SLICE-NN`, if that slice does not exist, if that slice does not plan each requirement that the test names, or if the package that plans one of these requirements is `Done`.
6. `make test` and CI run the test.
