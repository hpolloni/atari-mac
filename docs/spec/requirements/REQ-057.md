# REQ-057: Requirement status follows the plan

## Requirement

A requirement shall have the status `implemented` when, and only when, it is not withdrawn and its work package or its slice is `done`.

## Rationale

A reader of one requirement file must see whether the emulator implements it. Before this rule, each requirement stayed `draft`, also after its slice was done (for example REQ-080 after SLICE-07).

## Acceptance criteria

1. A requirement in a `done` package, or in a package of a `done` slice, with a status other than `implemented` or `withdrawn` makes the check fail. The message names the requirement, its slice and its package.
2. A requirement with the status `implemented` that is in no package, or in a package that is not `done` in a slice that is not `done`, makes the check fail.
3. A requirement with the status `withdrawn` makes no failure of criterion 1 or 2.
4. The status block of `README.md` gives the number of requirements with the status `implemented`.

## Notes

Project decision: a rule of the specification gates. The user asked for it on 2026-11-20.

The status values are: `draft` (written), `accepted` (reviewed, not yet implemented), `implemented` (its package is `done`) and `withdrawn`. When a change to an `implemented` requirement needs new work, the lead moves the requirement to a package that is not `done`, and sets the status to `draft` or `accepted`.
