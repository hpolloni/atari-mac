# REQ-432: Pseudo mode E after a mid-line GTIA mode

## Requirement

While `PRIOR` bits 6-7 are not `%00`, the emulator shall keep the hires state off, shall set the hires state on a horizontal blank code `%011` only while bits 6-7 are `%00`, and shall keep the hires state off for the rest of a scanline on which bits 6-7 return to `%00`.

## Rationale

Some demos change `PRIOR` in the middle of a scanline. On a hires line, the rest of the scanline then shows as low resolution colors.

## Acceptance criteria

In all criteria, `COLBK` = `$02`, `COLPF0-3` = `$14`, `$26`, `$38`, `$4A`, and the last horizontal blank code is `%011`. In criteria 1 and 2, `PRIOR` is `$00` during that code.

1. A write of `$40` to `PRIOR` takes effect at HPOS `$24` and a write of `$00` takes effect at HPOS `$28`. Then codes `%100`, `%101`, `%110`, `%111` at HPOS `$30-$33` give `$14`, `$26`, `$38`, `$4A` in both columns of each color clock.
2. On the next scanline, after the horizontal blank code `%011` and with `PRIOR` = `$00`, code `%101` gives `$38` in the left column and `$36` in the right column (hires pixels with the luminance of `COLPF1`).
3. `PRIOR` = `$40` during the horizontal blank code `%011` at HPOS `$00-$21`, and a write of `$00` takes effect at HPOS `$28`. Then codes `%100`, `%101`, `%110`, `%111` at HPOS `$30-$33` give `$14`, `$26`, `$38`, `$4A` in both columns of each color clock.

## Notes

Criterion 3 follows HRM 6.8: "High resolution mode is forced off whenever any of the GTIA special modes are active". The exact last HPOS at which a code `%011` sets the hires state is open (OI-054). The ACID800 test `gtia_psuedomodee` checks it.
