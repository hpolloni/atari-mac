# REQ-637: Disk image export

| Field | Value |
| --- | --- |
| Status | Draft |
| Priority | Must |
| Area | Media |
| Source | Project decision |
| Verification | Test |
| Depends on | REQ-625, REQ-630, REQ-632, REQ-015 |

## Requirement

The emulator shall give the frontend the current disk image as the bytes of an ATR file, with all writes and formats applied, and shall tell whether the image changed after it was inserted.

## Rationale

The user expects changes to a disk to stay. The emulation core has no file I/O (REQ-015), so the frontend writes the file.

## Acceptance criteria

The test images are the SD, ED and DD files of REQ-625 (data byte `i` holds `i & $FF`), with header bytes 7-15 set to `01 02 03 04 05 06 07 08 09`.

1. The SD file with 100 more bytes after the data, not changed: the export is equal to file bytes 0 to 92,175 (the input without the 100 bytes), and the image reports no change.
2. The DD file, not changed: the export is equal to the input file (183,952 bytes).
3. After Put sector 400 of the SD image with 128 bytes of `$5A`: the export loads with no error (REQ-625), and sector 400 holds 128 bytes of `$5A`. The image reports a change.
4. After Format `$21` of the ED image: the export has 92,176 bytes, header bytes 0-6 are `96 02 80 16 80 00 00`, and all data bytes are `$00`.
5. In criteria 1 to 4, export bytes 7-15 are `01 02 03 04 05 06 07 08 09`.
