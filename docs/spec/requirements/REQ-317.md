# REQ-317: CHBASE update timing

| Field | Value |
| --- | --- |
| Status | Draft |
| Priority | Should |
| Area | ANTIC |
| Source | HRM 4.4 Character modes (Character set storage) |
| Verification | Test |
| Depends on | REQ-313, REQ-316 |

## Requirement

The emulator shall use a new `CHBASE` value for character data fetches from the second cycle after the write, and shall store all bits 7-1 of the written value.

## Rationale

Software changes `CHBASE` in DLI handlers, and sometimes in the middle of a scan line. The new value takes effect two cycles after the write.

## Acceptance criteria

1. In a normal-width mode 2 line, `CHBASE` = `$E0`. A write of `$E4` to `CHBASE` on cycle 50 does not change the character data fetch on cycle 51: it reads an address in `$E000-$E3FF`.
2. In the same line, a write of `$E4` to `CHBASE` on cycle 49 changes the character data fetch on cycle 51: it reads an address in `$E400-$E7FF`.
3. After a write of `$E2` to `CHBASE`, a mode 2 character with name `$00` reads row 0 from `$E000`. In the next mode line, a mode 6 line, a character with name `$00` reads row 0 from `$E200`, with no new write.
