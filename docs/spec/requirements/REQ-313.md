# REQ-313: Character modes 2 and 3

## Requirement

The emulator shall show IR modes 2 and 3 as hi-res text, where each character name selects one of 128 characters at the character data address `(CHBASE & $FC) << 8 | (name & $7F) << 3 | row`, and each font bit gives one hi-res pixel.

## Rationale

Mode 2 is the standard 40-column screen of the OS (Graphics 0).

## Acceptance criteria

1. In a mode 2 line and in a mode 3 line, on row 0, a character with name `$01` and font byte `$9C` has the codes `%110`, `%101`, `%111` and `%100` on its 4 color clocks, left to right.
2. In a normal-width mode 2 line with names `$00` to `$27` and a different row 0 font byte for each name, positions `$30 + 4k` to `$33 + 4k` show the codes of the font byte of name k, for k = 0 to 39.
3. With `CHBASE` = `$E0` and a name of `$41`, the font fetch for row 0 reads `$E208` and the font fetch for row 5 reads `$E20D`. With a name of `$C1`, the font fetch for row 0 also reads `$E208`.
4. In mode 3, for a name of `$41`, rows 0-7 read font rows 0-7, and rows 8-9 have code `%100` on all color clocks (font data `$00`).
5. In mode 3, for names `$61` and `$E1`, rows 0-1 have code `%100` on all color clocks (font data `$00`), rows 2-7 read font rows 2-7, and rows 8-9 read font rows 0-1.
6. With `CHACTL` = `$02`, in mode 3, rows 8-9 of a character with name `$C1` have code `%111` on all color clocks (inverted `$00` data, project decision).

## Notes

Name bit 7 is an attribute bit for `CHACTL` (REQ-314). The HRM says "characters `$00-5F`" and "`60-7F`" for mode 3, and uses `$80-DF` for the same rule in HRM 4.7 (Mode lines with unusual height). This requirement applies the rule to name bits 6-5. TRN HW-II.A/Character-Display-Instructions and ANTIC-SPEC 6.5 give the same rule: "The last fourth of the character set (name bits 5 and 6 equal to one) is lowered."

The HRM does not say whether inversion (REQ-314) applies to the `$00` rows of mode 3. ACID800 antic_charcontrol says that it does. With `CHACTL` = `$02`, the test expects all pixels on in rows 8-9 of name `$81` and in rows 0-1 of name `$E0` in mode 3. With `CHACTL` = `$01`, it expects all pixels off in these rows. Thus ANTIC applies blink and inversion after it substitutes the `$00` data. Criterion 6 calls this a project decision. ACID800 now gives it.
