# REQ-101: One bus access in each CPU cycle

## Requirement

The emulator shall make exactly one bus access, read or write, in each CPU cycle, with the address, data and order of the NMOS 6502.

## Rationale

The 6502 uses the memory bus on every cycle without exception (HRM 3.3). Dummy cycles can change hardware state. For example, a read of a PIA data register clears pending interrupts. Cycle counts set the timing of all display effects.

## Acceptance criteria

1. For each of the 256 opcodes, the test `single_step_bus_cycles` runs all cases of the SingleStepTests 6502 file. For each case, the number of bus accesses is equal to the number of entries in the `cycles` list. Each access has the address, the value and the direction (read or write) of the entry at the same position.
2. `TXA` at `$0200` makes 2 bus accesses: a read of `$0200`, then a read of `$0201`. It makes no write.
3. Each CPU cycle (one call of `Cpu::tick`) makes exactly one bus access.

## Notes

The HRM gives the rules for dead cycles, but not a full table of cycles for each opcode. The SingleStepTests 6502 suite is the cycle reference (project decision). The longest documented instruction takes 7 cycles. Undocumented read-modify-write instructions with `(zp,X)` or `(zp),Y` take 8 cycles (HRM 3.4 Interrupt timing).
