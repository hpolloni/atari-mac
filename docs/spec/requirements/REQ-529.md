# REQ-529: Serial input errors

## Requirement

The emulator shall set `SKSTAT` bit 7 to 0 when a received stop bit is 0, shall set `SKSTAT` bit 5 to 0 when a byte completes while `IRQST` bit 5 is already 0, and shall keep these bits at 0 until a write to `SKRES`.

## Rationale

The OS SIO code reads `SKSTAT` after a frame and reports framing and overrun errors.

## Acceptance criteria

In all criteria, the setup and the frames are those of REQ-526.

1. A frame for `$43` with a stop bit of 0 makes `SKSTAT` bit 7 read 0, `SERIN` read `$43` and `IRQST` bit 5 read 0, all from the cycle on which `IRQST` bit 5 goes to 0.
2. Two frames, `$43` and then `$55`, with no write to `IRQEN` between them, make `SKSTAT` bit 5 read 0 after the second frame. `SERIN` reads `$55`.
3. Criterion 2 gives the same result when the test reads `SERIN` between the two frames.
4. With `IRQEN` = `$00`, the two frames of criterion 2 keep `SKSTAT` bit 5 at 1.
5. After criteria 1 and 2, the test clears `IRQST` bit 5 and sends a good frame. `SKSTAT` bits 5 and 7 still read 0. A write to `SKRES` on cycle X makes `SKSTAT` bits 5 and 7 read 1 from cycle X+1.

## Notes

TRN HW-III.H/SKSTAT says that bit 6 is the serial input overrun and bit 5 is the keyboard overrun. The HRM says that bit 5 is the serial input overrun and bit 6 is the keyboard overrun (HRM footnote 21, HRM 15.2 Errata). This requirement follows the HRM. TRN HW-II.C/Serial-Input, POKEY-SPEC 7 and ACID800 pokey_skstat also use bit 5 for the serial input overrun.
