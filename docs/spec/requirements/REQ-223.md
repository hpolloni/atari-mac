# REQ-223: Floating port B inputs

## Requirement

For port B bits 2-6 in input mode, the emulator shall read 1 for a delay after the bit changes from output 1 to input, and 0 after the delay or when the last output was 0.

## Rationale

On the 65XE, port B bits 2-6 are not connected and float. A bit that was output 1 reads as 1 for 100-500 ms after it becomes an input, then as 0 (HRM 2.5). The effect can be detected from BASIC.

## Acceptance criteria

1. `DDRB` = `$04`, port B output register = `$04`. A write sets `DDRB` = `$00`. A read of `PORTB` (`PBCTL` bit 2 = 1) 10 cycles after the write shows bit 2 = 1.
2. As in criterion 1, a read 178,977 NTSC machine cycles (100 ms) after the write shows bit 2 = 1.
3. As in criterion 1, a read 894,887 NTSC machine cycles (500 ms) after the write shows bit 2 = 0.
4. `DDRB` = `$04`, port B output register = `$00`. A write sets `DDRB` = `$00`. A read 10 cycles after the write shows bit 2 = 0.
5. Criteria 1 to 4 give the same results for bits 3, 4, 5 and 6.
6. While bits 2-6 read 1 as floating bits, CPU reads of `$C000`, `$A000` and `$5000` return the same values as before the write to `DDRB`.

## Notes

The HRM gives a range of 100-500 ms that changes between bits and systems. The emulator uses one fixed delay for all bits. The design gives the value (project decision).

FSM-800XL 1/Peripheral-Interface-Adaptor-PIA (Figure 1-7) names PB1 and PB3-PB6 "Not Used", and PB2 "Output To Led 1". The HRM says that bits 2-6 are not connected on the 800XL and the 65XE. This requirement follows the HRM. R6520 peripheral-io-ports and MCS6500-HW 1.5.4.1.2 say that a port B line in input mode goes to a high-impedance state (more than 1 megohm in MCS6500-HW), and that only the port A lines have passive pull-ups. This agrees with HRM 2.5.
