# REQ-506: Timer cycle timing

## Requirement

The emulator shall make each timer event visible in `IRQST` on the cycle that HRM 5.2 and HRM 5.3 give, relative to the `STIMER` write or to the `SKCTL` write that ends initialization mode.

## Rationale

Demos and some games use timer IRQs as exact raster timers. They need the event on the correct cycle.

## Acceptance criteria

In all criteria, the test writes `IRQEN` at least 10 cycles before the `STIMER` or `SKCTL` write.

1. With `AUDCTL` = `$40`, `AUDF1` = `$00`, `IRQEN` = `$01` and an `STIMER` write on cycle T, `IRQST` bit 0 reads 1 on cycle T+7 and 0 on cycle T+8.
2. With the setup of criterion 1 and `AUDF1` = `$05`, `IRQST` bit 0 reads 1 on cycle T+12 and 0 on cycle T+13.
3. With the setup of criterion 1, a second `STIMER` write on cycle T+4 makes `IRQST` bit 0 read 1 on cycles T+8 to T+11 and 0 on cycle T+12. A second `STIMER` write on cycle T+5 makes `IRQST` bit 0 read 0 on cycle T+8.
4. With the setup of criterion 1, an `AUDF1` = `$05` write on cycle T+2 makes `IRQST` bit 0 read 0 first on cycle T+13. An `AUDF1` = `$05` write on cycle T+3 makes `IRQST` bit 0 read 0 first on cycle T+8, and the second fire of timer 1 is on cycle T+17.
5. With `AUDCTL` = `$01`, `AUDF1` = `$00`, `IRQEN` = `$01`, `SKCTL` = `$00` for at least 114 cycles and an `STIMER` write while `SKCTL` = `$00`, a write of `SKCTL` = `$03` on cycle W makes `IRQST` bit 0 read 1 on cycle W+82 and 0 on cycle W+83.
6. With the setup of criterion 5 and `AUDCTL` = `$00`, `IRQST` bit 0 reads 1 on cycle W+23 and 0 on cycle W+24.
7. With `AUDCTL` = `$50`, `AUDF1` = `$00`, `AUDF2` = `$00`, `IRQEN` = `$02` and an `STIMER` write on cycle T, timer 1 fires on cycles T+8, T+15 and T+22, and timer 2 fires on cycles T+11, T+18 and T+25. `IRQST` bit 1 reads 1 on cycle T+10 and 0 on cycle T+11.

## Notes

Cycle numbers follow HRM 1.2 Conventions in this manual (Deadlines; Event timing): a write on cycle N is the write cycle of the instruction, and an event on cycle N is the first cycle in which a read shows it.

The HRM says that initialization mode must be held "long enough for both clocks to reset fully". It does not give the time. The 114 cycles in criterion 5 are a project decision for the test.

Criterion 7 follows from three HRM 5.3 statements: the linked period is N + 7, the high timer fires 3 cycles after the low timer, and the first IRQ has the same timing as an 8-bit timer (T+8).

The HRM gives the 15 kHz clock as a 7-bit polynomial counter (x^7 + x^6 + 1) and the 64 kHz clock as a 5-bit polynomial counter (x^5 + x^3 + 1). The emulator only needs the visible timing, so it can use plain counters.

ACID800 pokey_timertiming states that `IRQST` bit 0 reads 1 on cycle T+7 and 0 on cycle T+8 for `AUDF1` = `$00` on the 1.79 MHz clock (a value that it extrapolates), and checks the same timing for `AUDF1` = `$10` (T+24). It also checks the last `STIMER` write that prevents a fire (criterion 3), and the linked timers (criterion 7). ACID800 pokey_inittiming checks the cycle of the first timer 1 event after initialization mode for the 15 kHz and 64 kHz clocks (criteria 5 and 6).
