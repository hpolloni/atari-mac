# REQ-043: Requirement metadata in frontmatter

| Field | Value |
| --- | --- |
| Status | Draft |
| Priority | Must |
| Area | Quality |
| Source | Project decision |
| Verification | Test |
| Depends on | REQ-040 |

## Requirement

Each requirement file shall start with YAML frontmatter that holds its metadata, and the metadata shall pass a schema check.

## Rationale

A parser can read frontmatter without errors. A table in the body can change its layout and break a parser without an error.

## Acceptance criteria

1. The frontmatter has exactly these keys: `id`, `title`, `status`, `priority`, `area`, `source`, `verification`, `depends_on`.
2. `status` is one of `draft`, `accepted`, `withdrawn`. `priority` is one of `must`, `should`, `could`. `verification` is one of `test`, `inspection`, `demonstration`. `area` is one of the area names in `docs/spec/README.md`.
3. `id` equals the file name without `.md`, and each `id` is unique.
4. `depends_on` is a list of requirement IDs. Each ID exists, is not withdrawn, and is not the file's own ID.
5. The `depends_on` relation has no cycle.
6. A file that breaks one of criteria 1 to 5 makes the check fail. The failure message gives the file and the rule.

## Notes

Decided on 2026-11-19: YAML frontmatter, flat keys, with one list (`depends_on`). GitHub shows YAML frontmatter as a table.
