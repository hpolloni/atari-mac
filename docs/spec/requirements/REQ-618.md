# REQ-618: ACK and NAK timing

## Requirement

A disk drive shall start its ACK (`$41`) or NAK (`$4E`) byte for a command frame after the command line goes high, and no later than 16 ms after the command line goes high.

## Rationale

The ACK waits for the command line, so that the OS can set POKEY from send to receive. The OS waits for only about one video frame before it sends the command again. Thus the device must reply within 16 ms.

## Acceptance criteria

1. For the Status frame `31 53 00 00 84`, the command line stays low for 20,000 machine cycles after the stop bit of the last frame byte ends. The start bit of the ACK byte `41` begins at or after the cycle where the command line goes high.
2. For the Status frame, the start bit of the ACK byte begins no more than 28,636 machine cycles (NTSC) or 28,375 machine cycles (PAL) after the command line goes high.
3. Criteria 1 and 2 also apply to the NAK byte `4E` for the unsupported command frame `31 00 00 00 31`.
4. Criteria 1 to 3 pass for NTSC and for PAL.

## Notes

The cycle counts are 16 ms at the CPU clock of 1,789,772.5 Hz (NTSC) and 1,773,447.5 Hz (PAL), from the baud formula in HRM 10.3 Extended protocols, rounded down.

The exact delay in the window is a project decision. The design document gives the value.
