# REQ-060: Mutation testing of changed code

## Requirement

Each mutant that `cargo-mutants` makes in the lines that a change adds or modifies shall make at least one test fail, except the mutants that the mutation exclusion list names.

## Rationale

The coverage gate (REQ-042) shows that a test executes a line, not that a test checks the result of the line. A mutant that no test catches shows a missing check.

## Acceptance criteria

1. `make mutants` runs `cargo-mutants` (the version that `make tools` installs) on the lines of the diff from the merge base with `origin/main` to the working tree. `make check` calls `make mutants`.
2. A mutant with the result `missed` fails the gate, and the output gives the file, the line and the mutation. A mutant with the result `caught`, `timeout` or `unviable` passes.
3. The CI job `Mutants (cargo-mutants)` runs the same gate on Linux for the diff of each push to `main`, for the packages that the Linux jobs build. The job runs in shards (`Mutants (cargo-mutants) shard K/N`), and each shard tests a different part of the mutants. `CI success` needs all the shards.
4. The mutation exclusion list is the `exclude_re` list of `.cargo/mutants.toml`. Each entry has a comment line above it that gives the reason (for example, the mutant gives the same behavior). The lead decides each entry.
5. A change that adds or modifies no line of Rust code passes the gate without a mutant run.

## Notes

Project decision: the user asked for this gate on 2026-11-21. The gate runs only on changed lines because one run on the whole core takes hours. It is not in `make pre-commit` because it is too slow.
