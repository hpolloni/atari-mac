# REQ-125: CPU halt for ANTIC DMA

## Requirement

The emulator shall make no CPU bus access and no CPU state change in a machine cycle that ANTIC uses for DMA or refresh, and shall continue the CPU in the next free cycle.

## Rationale

ANTIC halts the 6502 for DMA and memory refresh (HRM 2.1, HRM 2.3). DMA contention sets the CPU speed for each display mode (HRM 3.3).

## Acceptance criteria

1. ANTIC uses cycles 20 to 29. `LDA $1000` makes its first bus access (opcode fetch) in cycle 19. Its other 3 bus accesses are in cycles 30, 31 and 32.
2. ANTIC uses cycles 20 to 29. `INC $0600` makes its opcode fetch in cycle 16 and reads `$0600` in cycle 19. It writes the old value in cycle 30 and the new value in cycle 31.
3. A test program of 10,000 instructions runs two times: without halted cycles, and with ANTIC halting every third machine cycle. The two runs give the same list of bus accesses (address, value, direction) and the same registers after each instruction.

## Notes

The HRM says that the CPU is blocked from the bus while ANTIC does a read cycle, and that dead cycles cannot be overlapped by DMA. The HRM does not state a different rule for CPU write cycles during DMA. The emulator halts read cycles and write cycles in the same way (project decision). TRN HW-II.A/Object-DMA-Direct-Memory-Access says that ANTIC sends HALT to the CPU, and that the CPU then goes to the tri-state condition for all of the next cycle. It does not state a different rule for write cycles either. The RDY behavior of `WSYNC` is different. REQ-126 covers it.
