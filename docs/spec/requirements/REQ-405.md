# REQ-405: Frame buffer format

## Requirement

The emulator shall output each frame as 384 x 240 GTIA color bytes, with one byte per half color clock, column `2 x (HPOS - $20) + h` (h = 0 for the left half) and row `scanline - 8`.

## Rationale

The HRM gives the wide playfield as HPOS `$20-$DF` (192 color clocks) and the visible scanlines as 8-247 (240 lines). One byte per half color clock holds the high resolution pixels of ANTIC modes 2, 3 and F. The frontend converts the bytes to RGB with the palette (REQ-409, REQ-410).

## Acceptance criteria

1. The frame buffer has 92160 bytes, in 240 rows of 384 bytes.
2. A single-width player with `GRAFP0` = `$80`, `HPOSP0` = `$80` and `COLPM0` = `$46` on scanline 100 sets columns 192 and 193 of row 92 to `$46`.
3. With `COLPF1` = `$3C` on a low resolution line, code `%101` at HPOS `$50` sets columns 96 and 97 to `$3C`.
4. A test makes frame N with `COLBK` = `$02` and frame N + 1 with `COLBK` = `$04`, with code `%000` at all visible color clocks. During all ticks of scanlines 8-247 of frame N + 1, all bytes of columns 4-379 of the frame buffer are `$02`. After the first tick of scanline 248 of frame N + 1, they are `$04`.

## Notes

Source: project decision for the layout. The HRM supplies the HPOS and scanline ranges. GTIA does not count vertical positions itself (HRM 6.2). It takes the scanline number from ANTIC.
