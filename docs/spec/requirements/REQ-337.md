# REQ-337: WSYNC deadline and read-modify-write

## Requirement

The emulator shall make a `WSYNC` write on cycle 104 or later wait until cycle 105 of the next scan line, and shall start a new wait for each write to `WSYNC`.

## Rationale

A late `WSYNC` write loses a full scan line. Some programs use `INC WSYNC` because it ignores DMA on the next cycle.

## Acceptance criteria

1. With `DMACTL` = `$00`, `STA WSYNC` has its write on cycle 104 of scan line N, followed by `STX $0600`. The `STX` opcode fetch is on cycle 105 of scan line N, and the `STX` write is on cycle 107 of scan line N + 1.
2. On the first scan line of a mode A line with `DMACTL` = `$23` (`Bitmap` fetch on cycle 104), `INC WSYNC` has its two write cycles on cycles 102 and 103, followed by `STX $0600`. The `STX` opcode fetch is on cycle 105, and the `STX` write is on cycle 108.
3. With `DMACTL` = `$00`, `INC WSYNC` has its two write cycles on cycles 103 and 104 of scan line N, followed by `STX $0600`. The `STX` opcode fetch is on cycle 105 of scan line N, and the `STX` write is on cycle 107 of scan line N + 1.
4. With `DMACTL` = `$00`, `STA WSYNC` has its write on cycle 113 of scan line N, followed by `STX $0600`. The `STX` opcode fetch is on cycle 0 of scan line N + 1, and the `STX` write is on cycle 107 of scan line N + 1.

## Notes

Acceptance criteria 2 and 3 follow from REQ-336: the 6502 ignores RDY on write cycles, and each write starts a wait. The 65C02 and 65C816 stop on write cycles. These CPUs are out of scope.
