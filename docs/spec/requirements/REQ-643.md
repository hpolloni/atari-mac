# REQ-643: Boot from cassette

## Requirement

With a boot tape inserted, START held at a cold reset and a key pressed after the OS prompt tone, the emulator shall boot the tape with AltirraOS through the POKEY serial input, with no shortcut of the OS cassette code.

## Rationale

Many games for the Atari 8-bit computers are on boot tapes. The OS reads the boot records from the cassette, puts them at the load address and runs the program.

## Acceptance criteria

The boot test tape is a CAS image that the test makes. It has a `FUJI` chunk, a `baud` chunk of 600 baud and two `data` chunks of 132 bytes: the first with a gap of 20000 ms, the second with a gap of 3000 ms. Each record is `55 55 FC`, 128 data bytes and the checksum (REQ-616) of the 131 bytes before it.

- Record 1 data: `00 02 00 07 86 07` (flags, 2 records, load address `$0700`, init address `$0786`), then `4C 80 07` (`JMP $0780`) at offset 6. The other bytes are `$00`.
- Record 2 data: `A9 A5 8D 00 06 18 60` (`LDA #$A5`, `STA $0600`, `CLC`, `RTS`) at offset 0. The other bytes are `$00`. The OS loads record 2 to `$0780`, so the init address `$0786` is the `RTS`.

The machine has AltirraOS, the BASIC ROM, no cartridge and no disk. The test holds START from the cold reset until frame 60, and presses RETURN from frame 180 to frame 186 (NTSC) or from frame 150 to frame 156 (PAL).

1. NTSC: `$0600` holds `$A5` within 2,400 frames after the cold reset.
2. PAL: `$0600` holds `$A5` within 2,000 frames after the cold reset.
3. NTSC: the motor line is high at the end of each frame before frame 180, and it is low at the end of at least one frame from frame 181 to frame 300.
4. The test tape with one bit of the checksum of record 2 changed: after 2,400 frames (NTSC), `$0600` does not hold `$A5`.
5. Criterion 1 passes with the SIOV shortcut on (REQ-623). The OS does the cassette requests with `DDEVIC` = `$60` or `$5F` (OI-046), and the shortcut does not handle them.

## Notes

TRN OS-10/Cassette-Booted-Software gives the conditions for a cassette boot: START pressed at power-on, the PLAY button pressed, and a key press after "the audio prompt by the cassette handler". It gives the boot record format: a flags byte that the boot does not use, the number of 128-byte records (1 to 255, 0 means 256), the load address and the init address. The OS loads the records to the load address, calls the load address + 6 with `JSR`, then calls the init address through `CASINI`, and then jumps through `DOSVEC`. It also says that the cassette motor still runs after the boot "due to a system bug". The test code does not stop the motor. TRN OS-APP-L.N/Diskette-Cassette-Boot gives the flag `CKEY`, which the OS sets when START is pressed during the power-up.

FAQ 1.7 (the 65XE): with BASIC, hold START at power-on; with no cartridge and without BASIC, hold START and OPTION. The test keeps BASIC on, because the test program does not use `$A000-$BFFF`.

TRN SRC-CASORG (assembler lines 3163-3180) gives the OPEN for input of the 400/800 OS: one prompt tone, a wait for a key, the motor on (`$34` to `PACTL`), and then a wait of `$0240` frames (NTSC, 9.6 s) or `$01E0` frames (PAL, 9.6 s) "for motor to come up to speed". TRN SRC-SIOORG (assembler lines 2236-2245) then waits for the read inter-record gap time before it measures the baud rate. The gap of 20000 ms of record 1 is longer than these waits, as the 20-second leader of FAQ 7.1.6 is. To verify: the same waits in AltirraOS. The frame limits of criteria 1 and 2 have a margin of approximately 25 percent for this.

TRN OS-APP-L.D says that the OS measures the baud rate from the `$55 $55` bytes at the start of each record, and can theoretically handle 318 to 1407 baud. HRM 4.16 (Atari OS C: handler) describes a bug in this measurement: the OS can rarely compute a bad baud rate because of the read of `VCOUNT` near the vertical blank. The emulator does not change this behavior.

The key timing of the test (START until frame 60, RETURN at frame 180) is a project decision. To verify: that AltirraOS accepts the RETURN key at frame 180 (after its prompt tone).

Criterion 5 does not depend on the decision of OI-046: for both values, the SIOV shortcut handles only the bus ID `$31` (REQ-624).
