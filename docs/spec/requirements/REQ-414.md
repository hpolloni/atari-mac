# REQ-414: P/M DMA data path and GRACTL

## Requirement

The emulator shall load the missile DMA byte from ANTIC into `GRAFM` when `GRACTL` bit 0 = 1, and each player DMA byte into `GRAFPn` when `GRACTL` bit 1 = 1, and shall keep the old latch value otherwise.

## Rationale

Most programs use ANTIC DMA to get P/M data. GTIA must accept the data, so both `DMACTL` in ANTIC and `GRACTL` in GTIA must enable it. ANTIC fetches the missiles on cycle 0 and the players on cycles 2-5 of each scanline 8-247.

## Acceptance criteria

In all criteria, `HPOSP0` = `$80`, `HPOSM0` = `$90`, `COLPM0` = `$46`, `COLBK` = `$02` and single width, except where the criterion states other values. "A DMA byte" is a byte that ANTIC gives to GTIA in the P/M DMA cycle of the object.

1. With `GRACTL` = `$03` and a player 0 DMA byte of `$80` on even scanlines and `$40` on odd scanlines, each even row shows `$46` at HPOS `$80` only and each odd row shows `$46` at HPOS `$81` only.
2. With the DMA bytes of criterion 1 and a write of `$00` to `GRACTL` in cycle 110 of scanline 99, rows 92-239 (scanlines 100-247) all show `$46` at HPOS `$81` only.
3. With `GRACTL` = `$02`, a CPU write of `$03` to `GRAFM` before scanline 8 and a missile DMA byte of `$00` on each scanline, HPOS `$90-$91` show `$46` on all rows.
4. With `GRACTL` = `$01`, a missile DMA byte of `$03` and a player 0 DMA byte of `$80` on each scanline, and `GRAFP0` = `$00`, HPOS `$90-$91` show `$46` and HPOS `$80` shows `$02` on all rows.
5. With `GRACTL` = `$00`, and again with `GRACTL` = `$03`, a CPU write of `$80` to `GRAFP0` in horizontal blank after the player DMA cycle makes HPOS `$80` of that scanline show `$46`.
6. On the full machine, with one-line P/M DMA in `DMACTL`, `GRACTL` = `$03` and player 0 data in memory that is `$80` for even scanlines and `$40` for odd scanlines, the frame buffer gives the result of criterion 1.

## Notes

ANTIC does the fetch and its timing (ANTIC requirements, REQ-3xx). Behavior when `GRACTL` enables DMA that `DMACTL` does not enable is in REQ-441.
