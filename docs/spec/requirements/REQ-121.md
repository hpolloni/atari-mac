# REQ-121: Taken branch interrupt delay

| Field | Value |
| --- | --- |
| Status | Draft |
| Priority | Should |
| Area | CPU (6502C) |
| Source | HRM 3.4 Interrupts (Taken branch delay) |
| Verification | Test |
| Depends on | REQ-106, REQ-118 |

## Requirement

The emulator shall delay interrupt service by one instruction after a taken branch that does not cross a page, when the interrupt would otherwise start directly after that branch.

## Rationale

This effect changes the DLI and IRQ entry timing in loops that wait with a branch.

## Acceptance criteria

1. Start: `Z` = 0. A `BNE` to a target on the same page runs in cycles C to C+2. The target is a `NOP`. The NMI line goes high in cycle C+1. The `NOP` executes in cycles C+3 and C+4. The NMI sequence starts in cycle C+5.
2. As in criterion 1, but the NMI line goes high in cycle C. The NMI sequence starts in cycle C+3, directly after the `BNE`.
3. Start: `Z` = 0. A `BNE` to a target on a different page runs in cycles C to C+3. The NMI line goes high in cycle C+2. The NMI sequence starts in cycle C+4, directly after the `BNE`.
4. Start: `Z` = 1. A `BNE` that is not taken runs in cycles C and C+1. The NMI line goes high in cycle C. The NMI sequence starts in cycle C+2.
5. `JMP abs` runs in cycles C to C+2. The NMI line goes high in cycle C+1. The NMI sequence starts in cycle C+3. `JSR abs`, `RTS` and `RTI` each run in cycles C to C+5. The NMI line goes high in cycle C+4. The NMI sequence starts in cycle C+6.
6. With `I` = 0 and the IRQ line asserted instead of the NMI line, criteria 1 to 5 give the same cycles for the IRQ sequence. (For `RTI`, the pulled `P` has `I` = 0.)
