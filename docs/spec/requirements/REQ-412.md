# REQ-412: PAL chroma blending

## Requirement

The emulator shall have an optional PAL display filter that averages the chroma of each scanline with the chroma of the previous scanline and keeps the luma of the current scanline, and the filter shall be off by default.

## Rationale

Some PAL programs alternate GTIA mode 9 and mode 11 lines to show more colors. Many PAL TVs average chroma with a delay line, and these programs need that effect.

## Acceptance criteria

In these criteria, the filter works on PAL palette colors before the clamp. Y is `L / 15` of the byte.

1. With the default frontend settings, the RGB value of each frame buffer byte b is `palette::rgb(PAL, b)` (the filter is off).
2. With the filter on, the output of each pixel of rows 1-239 is `Y2 + ((RGB1 - Y1) + (RGB2 - Y2)) / 2` for each channel, then clamped to 0-1 and converted with `round(255 x value)`. RGB1 and Y1 are from the same column of the previous row, and RGB2 and Y2 are from the current row.
3. With the filter on, a row of `$08` above a row of `$48` gives (167, 116, 159) on the second row, with a tolerance of 1 for each channel.
4. With the filter on, a row of `$48` above a row of `$08` gives (167, 116, 159) on the second row, with a tolerance of 1 for each channel.
5. With the filter on, a row of `$48` above a row of `$C8` gives (154, 133, 103) on the second row, with a tolerance of 1 for each channel.
6. With the filter on, the output of each pixel of row 0 is `palette::rgb(PAL, b)` of its own byte b (row 0 has no previous row).

## Notes

This is a TV effect. The frame buffer (REQ-405) does not change. Row 0 is not blended (OI-021, decided). The frontend flag `--pal-blending` turns the filter on (REQ-019).
