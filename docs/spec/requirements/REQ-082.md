# REQ-082: Turbo while the tape motor runs

## Requirement

While a tape is inserted and the cassette motor line is low, the frontend shall run the emulation without the real-time frame pacing (turbo), and shall show a frame at least every 100 ms of host time.

## Rationale

A tape loads at 600 baud. A boot-tape game takes some minutes in real time, and the gap before the first record can be 30 s or more. With turbo, the same load takes seconds, and the emulated machine stays exact to the cycle, so each tape loader works.

## Acceptance criteria

1. With a tape inserted, the frontend uses turbo in each frame that starts while the motor line is low (CA2 low, REQ-641), and real-time pacing (REQ-007) in each frame that starts while the motor line is high.
2. Without a tape, the motor line has no effect on the pacing.
3. In turbo, the frontend shows a frame at least every 100 ms of host time.
4. The emulated machine does not depend on turbo: after the same frames and the same key input, the frame buffer and the RAM are the same with turbo and without turbo.
5. In turbo, the frontend plays no audio, and this does not count as an underrun (REQ-011). The audio plays again when real-time pacing starts again.

## Notes

Project decision (OI-051, option 2, decided by the user on 2026-11-20). The HRM does not cover it. The turbo of `--bas` (REQ-080 criterion 7) uses the same rule for the frame display.

The load time with turbo depends on the speed of the host.
