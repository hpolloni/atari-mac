# REQ-520: Debounce off and scan off

## Requirement

The emulator shall pass every compare-register check of the scan state machine when `SKCTL` bit 0 is 0, and shall hold the state machine in state 0 and the scan counter in reset when `SKCTL` bit 1 is 0.

## Rationale

Some programs change `SKCTL` and expect the real side effects. The OS sets `SKCTL` bits 0 and 1 for normal typing.

## Acceptance criteria

In all criteria, `IRQEN` = `$40`.

1. With `SKCTL` = `$02` and only L (`$00`) down for 300 x 114 cycles, `IRQST` bit 6 reads 1, `SKSTAT` bit 2 reads 1 and `KBCODE` does not change.
2. With `SKCTL` = `$02` and L (`$00`) and J (`$01`) down, `KBCODE` reads `$01` and `IRQST` bit 6 reads 0 within 65 x 114 cycles. While both keys stay down, `SKSTAT` bit 2 changes to 0 every 64 x 114 cycles and reads 0 for 2 x 114 cycles each time.
3. With `SKCTL` = `$03`, Shift up and the A key registered and down, a write of `SKCTL` = `$01` makes `SKSTAT` bit 2 read 1 within 114 cycles. Then, with A, Shift and BREAK down for 300 x 114 cycles and `IRQEN` = `$C0`: `SKSTAT` bit 2 reads 1, `KBCODE` reads `$3F`, `IRQST` bits 6 and 7 read 1, and `SKSTAT` bit 3 reads 1 (its value before the write).
4. With `SKCTL` = `$03` and the A key registered and down, a write of `SKCTL` = `$02` makes `SKSTAT` bit 2 read 1 within 3 x 114 cycles. `SKSTAT` bit 2 then reads 1 for 300 x 114 cycles while only the A key stays down.

## Notes

With debounce off, holding two adjacent keys makes the second key register once every 64 scanlines. The HRM states that the keyboard is "basically non-functional" in this mode.

POKEY-SPEC 3 states that with debounce off, POKEY forces the compare signal of the binary counter and the compare latch to true.
