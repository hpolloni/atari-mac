# REQ-231: Spurious CA2 and CB2 interrupts

## Requirement

The emulator shall set control register bit 6 when CA2 changes from output low to a positive edge input mode, or when CB2 changes from output high, after a low-to-high output change, to any input mode.

## Rationale

The CB2 case is part of the normal SIO protocol. A write of `$08` to `PBCTL` can cause an endless series of interrupts if no IRQ routine clears them (HRM 2.5).

## Acceptance criteria

1. Writes of `$34` and then `$14` to `PACTL` (bits 5-3 = `110`, then `010`). `PACTL` bit 6 = 1, and the PIA does not assert IRQ.
2. Writes of `$34` and then `$1C` to `PACTL` (bits 5-3 = `110`, then `011`). `PACTL` bit 6 = 1, and the PIA asserts IRQ.
3. Writes of `$34`, `$3C` and then `$08` to `PBCTL` (bits 5-3 = `110`, `111`, then `001`). `PBCTL` bit 6 = 1, and the PIA asserts IRQ.
4. After a PIA reset, writes of `$3C` and then `$00` to `PBCTL` (bits 5-3 = `111` with no earlier `110`, then `000`). `PBCTL` bit 6 stays 0.

## Notes

The HRM says that the CA2 output must have been low recently. It does not give a time. The emulator uses the last output mode before the change, with no time limit (project decision). Criterion 4 is the project reading of the CB2 condition.
