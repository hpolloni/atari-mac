# REQ-216: Power-on reset

## Requirement

At power-on, the emulator shall reset the CPU, ANTIC, GTIA, POKEY and the PIA, and shall then start the CPU reset sequence.

## Rationale

The OS cold start begins at the reset vector with all chips in a known state.

## Acceptance criteria

1. A test OS image has bytes `$3FFC` = `$34` and `$3FFD` = `$C2`. After power-on, the first 7 CPU cycles are reads with no write. The eighth CPU cycle fetches the opcode at `$C234`.
2. After power-on, CPU reads of `$D302` and `$D303` return `$00`, and CPU reads of `$D300` and `$D301` return `$00` (`DDRA` and `DDRB`, REQ-230).
3. A test OS image waits for 3 frames, then writes `$C0` to `NMIEN`, `$22` to `DMACTL`, and `$FF` to each register in `$D000-$D01F` and `$D200-$D20F`, and then loops. Machine A is new. Machine B runs the image for 10 frames and then does a power-on. In the 2 frames after power-on, A and B make the same CPU bus accesses in the same machine cycles.
4. With AltirraOS and Altirra BASIC, `screen_text` shows the row `Ready` (Altirra BASIC, REQ-005) within 300 frames after power-on.

## Notes

The reset states of GTIA and POKEY are in the REQ-400 and REQ-500 ranges. The limit of 300 frames in criterion 4 is a project value.

POKEY has no reset pin (HRM 5.7). Here, "reset POKEY" means `Pokey::reset`, which sets the power-on state of REQ-501. The machine calls it only at power-on (OI-009).
